# Design

## Context

Кодовая база: ~9 тысяч строк Rust в 15 модулях (`src/`), 7 продуктовых спецификаций в `openspec/specs/`. В `.zcode/skills/` уже живут workflow-скилы (`git`, `openspec-*`); доменных скилов нет. Продуктовые спеки описывают нормативное поведение («что должно»), но не говорят, где и как это устроено в коде — именно этот разрыв агенты закрывают чтением исходников на каждой задаче. Мотивация — в proposal.md (Why).

## Goals / Non-Goals

**Goals:**

- Скил на каждый домен + один общий скил `minisnap-architecture`; пять скилов в `.zcode/skills/`.
- Скил заменяет первичное исследование кода: карта модулей, поток данных, инварианты, грабли; точные детали — по адресам в код, а не пересказом.
- Загрузка по триггеру: задача домена грузит только его скил; задача на ориентацию — только общий.
- Правило синхронизации скилов с кодом, зафиксированное в AGENTS.md.

**Non-Goals:**

- Не пересказываем нормативное поведение продукта — оно в `openspec/specs/`, скил даёт на них ссылки.
- Не делаем справочник всех функций и сигнатур — скил даёт адрес (файл, тип, функция), а не копию кода.
- Не трогаем продуктовый код, зависимости и workflow-скилы (`git`, `openspec-*`).

## Decisions

### 1. Скил на домен; общий слой — отдельный скил `minisnap-architecture`

Выбор пользователя. Альтернативы, которые отвергнули:

- **Один скил `minisnap` с references на домены** — один триггер на любую задачу, но доменные задачи платят за загрузку карты; хуже Matches точность триггера.
- **Каталог общего слоя без SKILL.md** («глобальные references», достижим только по ссылке из доменных скилов) — механически работает, но общий слой не срабатывает сам на задачах планирования (`/opsx:propose`) и кросс-доменных рефакторингах, где исследование кода дороже всего.
- **Ссылки между доменными скилами** (references одного скила из другого) — сцепляют скилы, ломаются при переименовании; отвергнуто.

`minisnap-architecture` — полноценный скил со своим триггером (ориентация, планирование change, кросс-доменные задачи); доменные скилы ссылаются только на него.

### 2. Границы доменов — по модулям и спецификациям

| Скил | Модули | Продуктовые спеки |
|---|---|---|
| `minisnap-shell` | `app.rs`, `config.rs`, `prefs.rs`, `hotkeys.rs`, `permission.rs` | `tray-app`, `global-hotkeys`, `preferences`, `screen-recording-permission` |
| `minisnap-capture` | `capture.rs`, `overlay.rs` | `frozen-capture` |
| `minisnap-output` | `output.rs` | `capture-output` |
| `minisnap-editor` | `editor_window.rs`, `src/editor/` (`mod`, `render`, `hit_test`, `session`, `text`) | `shot-editor` |

`minisnap-architecture` покрывает: карту всех модулей одной таблицей, сквозной поток «хоткей → оверлей → захват → вывод → редактор» (кто кого запускает, какие данные передаются), и сквозные конвенции — системы координат (пункты AppKit против пикселей CG, scale factor, flipped-координаты), владение и время жизни `CGImage`, objc2-паттерны (`MainThreadMarker`, `Retained`, block2-callbacks), контракт заморозки T0. Регистрация хоткеев живёт в `shell`, маршрутизация действий хоткеев по доменам — в карте `architecture`.

Границы совпадают с границами существующих capability, чтобы «какая спека закрывает этот модуль» решалось без поиска.

### 3. Формат SKILL.md: карта, поток, инварианты, адреса

Одинаковый скелет у всех доменных скилов:

1. «Что это за домен» — 2–3 предложения и границы (что сюда не входит).
2. Карта модулей — таблица «модуль → ответственность → ключевые типы».
3. Поток данных домена — от входа к выходу, с названиями реальных функций как якорей.
4. Инварианты и грабли — то, что агент сейчас выясняет чтением кода: неочевидные договорённости между модулями, тонкости координат, порядок владения.
5. Ссылки: на продуктовые спеки домена и на `minisnap-architecture` для сквозных конвенций.

`minisnap-architecture` вместо потока домена несёт общий поток и конвенции. Бюджет SKILL.md — 10 000 символов (спека); всё, что не влезает или нужно редко, уходит в `references/` внутри скила с указателями из SKILL.md. Ожидаемо references понадобятся editor (крупнейший домен, ~4,9 тыс. строк) и, возможно, capture; shell и output, скорее всего, уместятся целиком.

### 4. Язык: тело — русское, frontmatter — английский

Тело скилов — русский с английскими идентификаторами и путями, как продуктовые спеки: их читает и агент, и пользователь. Frontmatter-описание (`description`, по которому срабатывает триггер) — английское, как у всех установленных скилов в этом окружении; семантика триггера не зависит от языка запроса.

### 5. Достоверность: адреса вместо пересказа, проверка при написании

Скил упоминает только те пути, типы и функции, что существуют в коде на момент написания; методика применения (apply) — прочитать модули домена целиком и дистиллировать, а не писать по памяти. Финальная задача apply — прогнать упомянутые в скилах пути и символы проверкой существования (`grep`/`ls`), чтобы не осталось битых адресов.

### 6. Синхронизация — правило в AGENTS.md

В AGENTS.md добавляется короткий раздел: перечень скилов с доменами и правило «правка, меняющая поведение или структуру модулей домена, обновляет скил этого домена в том же change». Автоматической проверки нет — осознанный компромисс (см. Risks).

## Risks / Trade-offs

- [Скилы устаревают при правках коде без обновления скилов] → правило синхронизации в AGENTS.md (агент на apply видит его каждый раз); при `/opsx:archive` change, менявший домен, напоминает проверить скил — правило также попадает в привычный поток работы.
- [Ложная уверенность: агент верит скилу, а не коду] → скилы дают адреса в код для проверки деталей и отсылают к спекам за нормативом; в SKILL.md явно написано «перед правкой проверь актуальный код по адресу».
- [Триггер-шум: пять описаний в системном списке] → описания разнесены по доменам, `minisnap-architecture` срабатывает только на ориентацию/планирование/кросс-доменные задачи; цена лишней строки в списке — единицы токенов.
- [Пересказ вместо карты: скилы разбухают] → жёсткий бюджет 10 000 символов на SKILL.md и прогрессивная загрузка через `references/`.

## Migration Plan

Изменение чисто аддитивное: новые каталоги в `.zcode/skills/` плюс короткая правка AGENTS.md. Продуктовый код не трогается, `cargo`-артефакты не меняются. Откат — удалить пять каталогов и секцию из AGENTS.md (или `git revert`).
