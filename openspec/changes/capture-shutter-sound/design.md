# Design

## Context

См. proposal.md — Why. Технические факты:

- У minisnap уже есть единственная точка «снимок состоялся»: обработчик
  `OverlayOutcome::Selected` в `src/app.rs:760` (главный поток, тик) — туда
  приходят все виды захвата (регион / окно / весь экран), там же идут
  `crop` → `copy_to_pasteboard` → `save_to_file`.
- Звуковой фидбек в приложении отсутствует; звуковых ассетов в бандле нет.
- Проверено на этой машине (macOS 26.5): старый путь звука затвора
  `/System/Library/PrivateFrameworks/ScreenCapture.framework/.../camera-shutter.aiff`
  не существует; системные UI-звуки переехали в
  `/System/Library/Components/CoreAudio.component/Contents/SharedSupport/SystemSounds/system/`,
  где есть `Shutter.aif` (рядом `Grab.aif` и `Screen Capture.aif`).
- Зависимости: `objc2-app-kit 0.3` подключён поэлементно, feature `NSSound`
  есть в крейте, но пока не включён; `objc2-core-foundation 0.3.2` уже в
  дереве (транзитивно), у него есть feature `CFPreferences` — чтение
  системного ключа `disable-sound` не тянет новых экосистем.

## Goals / Non-Goals

**Goals:**

- Звук как у системной утилиты, в момент завершения выделения, без новых
  крейтов и без аудио-ассетов в бандле.
- Мягкая деградация: нет файла или нет разрешения на чтение — снимок
  продолжается без звука и без ошибок.
- Уважение системного выключателя `com.apple.screencapture disable-sound`.

**Non-Goals:**

- Собственная настройка звука в config/prefs minisnap — управление тем же
  системным ключом, что и у системной утилиты (допущение из proposal).
- Визуальная вспышка экрана (у системной утилиты она отдельная фича).
- Звук при действиях редактора (⌘C, сохранение) — только на момент съёмки.

## Decisions

### D1. Источник звука — системный файл по цепочке известных путей; воспроизведение через `NSSound`

Цепочка, берётся первый существующий путь (проверка `[NSFileManager fileExistsAtPath:]`):

1. `/System/Library/Components/CoreAudio.component/Contents/SharedSupport/SystemSounds/system/Shutter.aif` — macOS 26+ (проверено на 26.5);
2. `/System/Library/PrivateFrameworks/ScreenCapture.framework/Versions/A/Resources/camera-shutter.aiff` — исторический путь, на который опирались сторонние утилиты (macOS 12–15);
3. ничего не найдено — тихо, без звука.

Воспроизведение: `NSSound(contentsOf:)` + `play` из главного потока.
Альтернативы:

- **Ассет в бандле приложения** — нет подходящего звука, а копия системного
  поднимает вопросы распространения Apple-ассетов; отклонено.
- **AudioToolbox / `AudioServicesCreateSystemSoundID`** — тот же файл на
  входе, но добавляет прямой зависимый крейт `objc2-audio-toolbox` ради
  уже решённой `NSSound`-ом задачи; отклонено.
- **Подпроцесс `afplay`** — процесс на каждый снимок, латентность запуска,
  мусор в `ps`; отклонено.

`NSSound` играет на текущее устройство вывода с системной громкостью,
поддерживает AIFF/CAF/WAV — покрывает оба файла цепочки.

### D2. Точка вызова — `OverlayOutcome::Selected` в `src/app.rs`, сразу после успешного `crop`

Порядок в обработчике: `crop` дал непустой кадр → звук → буфер → файл.
Звук означает «снимок сделан», поэтому не ждём завершения сохранения
(системная утилита играет звук в момент съёмки, а не по окончании записи);
пустой `crop` (вырожденный случай) звуком не подтверждаем. Одна точка
гарантирует один звук на снимок независимо от числа дисплеев.

Альтернатива: играть внутри `Overlay::finish` в момент `mouseUp` — раньше на
толщину fade-out оверлея (<100 мс), но размазывает фидбек по
capture-домену и требует прокидывать вызов в оверлей; отклонено.

### D3. `disable-sound` читается на каждом снимке через `CFPreferencesCopyAppValue`

`objc2-core-foundation` с feature `CFPreferences`, домен
`com.apple.screencapture`, ключ `disable-sound`, значение — `CFBoolean`.
Без кеширования: чтение копеечное, ключ меняется вне приложения.
Ключ отсутствует или не `true` — звук играется. Ошибка чтения трактуется
как «звук включён» и не прерывает снимок.

### D4. Новый модуль `src/sound.rs`

Одна публичная функция `play_shutter()` — best-effort, без `Result`:
неудачи (нет файла, не создался `NSSound`) глотаются с записью в stderr
по образцу остальных best-effort мест (`enforce_retention`). Не размещаем
в `output.rs`, чтобы не смешивать фидбек с логикой файлов/буфера; вызов —
одна строка из `app.rs`.

Доменная принадлежность: спека живёт в `capture-output`, поэтому обновление
скилла `minisnap-output` (карта модулей + поток данных) входит в ту же
правку — по правилу AGENTS.md об обновлении доменных скиллов.

### Гочар `NSSound`: объект должен жить до конца воспроизведения

Если `NSSound` инстанс создать локально и уронить, звук обрежется.
Инстанс удерживается до конца воспроизведения — например, в static
(переиспользуемый игрок; повторный `play` на том же инстансе перезапускает
звук с начала, что как раз нужно при быстрых повторных снимках).

### D5. Прогрев аудио на старте приложения (по итогам живой проверки)

Первый в жизни процесса `play` стоит ~0.8 с (инициализация аудиостека
CoreAudio), холодное чтение `CFPreferences` — ~0.15 с; тёплые вызовы —
микросекунды. Вызов звука сидит в главном потоке вместе с fade-out
оверлея (`orderOut` оверлея — в completion-блоке анимации), поэтому без
прогрева первый снимок после запуска задерживал и звук, и пропадание
оверлея почти на секунду — заметил пользователь на живой проверке.

`sound::prewarm()` при старте: pref-read, загрузка плеера из цепочки и
одно беззвучное воспроизведение (`setVolume(0)` → `play` → `stop` →
`setVolume(1)`) — открывает аудиоустройство без щелчка. Вызов —
одноразовый `NSTimer` через ~1 c после старта runloop в `app::run()`,
чтобы прогрев не отодвигал появление трея и первый рендер.

Альтернатива «играть звук из фонового потока» отклонена: она разблокировала
бы UI, но сам звук всё равно запаздывал бы на те же ~0.8 с — прогрев
устраняет причину, а не перекладывает цену.

## Risks / Trade-offs

- [Системный путь звука переедет в будущих macOS] → цепочка известных путей
  плюс тихая деградация; новый путь добавляется одной строкой.
- [`Shutter.aif` может оказаться не тем звуком, что играет системная утилита
  (рядом лежат `Grab.aif` и `Screen Capture.aif`)] → механизм один и тот же
  для любого файла цепочки; при применении сверить на слух одним реальным
  снимком и при расхождении заменить имя файла в одном месте (см. Open
  Questions).
- [Повторный снимок раньше конца звука] → один переиспользуемый инстанс
  `NSSound`: повторный `play` перезапускает воспроизведение, наложения нет.

## Migration Plan

Не требуется — аддитивное поведение, обычная пересборка; откат — исключение
вызова из `app.rs`.

## Open Questions

- Какой из файлов (`Shutter.aif` / `Screen Capture.aif`) действительно
  играет системная утилита на macOS 15/26, можно закрыть только на слух при
  применении; на архитектуру не влияет.
