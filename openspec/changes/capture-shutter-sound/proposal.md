# Proposal

## Why

Системная утилита скриншотов macOS (⌘⇧3/4/5) в момент съёмки издаёт короткий
щелчок затвора камеры — привычное звуковое подтверждение «снимок сделан».
minisnap захватывает тихо: пользователь, уже отвлёкшийся от экрана после
завершения выделения, не получает мгновенного подтверждения, что снимок
состоялся. Поведение должно совпадать с системной утилитой.

## What Changes

- При успешном завершении выделения minisnap издаёт звук затвора камеры —
  тот же, что играет системная утилита скриншотов.
- Звук — системный файл ОС, а не ассет приложения: известные пути
  (`Shutter.aif` в CoreAudio.component на macOS 26+,
  `camera-shutter.aiff` в ScreenCapture.framework на более старых версиях)
  проверяются по цепочке; если ни один не найден — снимок делается молча,
  без ошибки и без падения.
- Уважается системный выключатель звука скриншотов
  `defaults write com.apple.screencapture disable-sound -bool true` —
  как у системной утилиты.
- При отмене захвата (Esc, клик по вуали, смена конфигурации дисплеев) звук
  не играется. Звук играется один раз на снимок независимо от числа дисплеев.
- Предполагается (и фиксируется здесь как допущение): собственной настройки
  в config/prefs minisnap не добавляется — управлять звуком можно тем же
  системным ключом, что и звук системной утилиты.

### Modified Capabilities

- `capture-output`: добавляется requirement о звуковом подтверждении — при
  завершении выделения приложение издаёт звук затвора, если системный звук
  скриншотов не выключен; при отмене захвата звука нет.

## Impact

- `src/app.rs` — обработчик `OverlayOutcome::Selected`: вызов воспроизведения
  звука в главном потоке рядом с `crop`/`copy_to_pasteboard`/`save_to_file`.
- Новый небольшой модуль воспроизведения звука (расположение — design.md),
  зависимость — только `NSSound` из `objc2-app-kit` (добавить feature в
  `Cargo.toml`); новые внешние крейты и аудио-ассеты не нужны.
- При архивации изменения — пополнение `openspec/specs/capture-output/spec.md`.
