# Design

## Context

Мост `minisnap-mcp` — однопоточный stdio-сервер: `tools/list` отдаёт каталог с описаниями, `tools/call` через `call_tool()` делает один HTTP-запрос к agent-серверу выбранного инстанса и оформляет ответ (`format_result`). `action` и `editor` форвардят serde-формы `AgentAction`/`AgentEditorOp` как есть; конвенция моста — «добавляет никакого поведения своего». Тест `tools_list_has_six_tools` фиксирует число инструментов.

## Goals / Non-Goals

**Goals:**
- N последовательных вызовов `action`/`editor` — одним вызовом инструмента, с читаемым отчётом по каждому шагу.
- Шаги идут теми же кодовыми путями, что и раньше: тот же `POST /action`, тот же `POST /editor`.

**Non-Goals:**
- Не менять приложение: ни протокола (`agent_proto.rs`), ни agent-сервера, ни диспетчера — поэтому не нужен ни ребилд бандла, ни перезапуск работающего инстанса.
- Не делать батч транзакцией: нет отката исполненных шагов при ошибке — undo доступен агенту как обычный шаг.
- Не включать в батч чтения (`state`, `screenshot`, `log`) — они остаются одиночными.

## Decisions

1. **Батч живёт в мосте, а не в приложении.** Обработчик батча — цикл по шагам в `call_tool()`, каждый шаг — обычный `http_json` к существующему эндпоинту. Альтернатива — `POST /batch` в agent-сервере с диспетчеризацией списка в главном потоке — даёт только экономию TCP-коннектов, которой ничего не покупает (доминирующая задержка — MCP-раунд-трип, не локальный HTTP), но требует менять протокол, пересобирать и перезапускать приложение. Мостовой вариант меняет один файл и исполняет шаги ровно теми же путями, что одиночные инструменты.

2. **Шаг повторяет аргументы одиночных инструментов.** Шаг — объект ровно с одним ключом `action` или `editor`; значение — та же serde-форма, которую агент уже передаёт одиночному инструменту. Агент собирает батч копированием уже знакомых форм, ничего нового учить не надо. Шаг с обоими ключами, без них или с лишними — ошибка вызова с номером шага, до исполнения чего-либо (весь список валидируется заранее).

3. **Останавливает только транспорт; статусы — нет.** Транспортная ошибка (connect, таймаут, не-JSON) означает «дальше собирать нечего» — исполнение прекращается, ответ-ошибка перечисляет исполненные шаги со статусами. `done`/`initiated`/`rejected`/`noop` и error-конверты приложения — легитимные ответы шагов: `rejected` одного шага (например, `FinishText` без открытого ввода) не делает бессмысленными следующие, а остановка по нему заставила бы агента собирать оставшиеся шаги повторными раунд-трипами — ровно то, от чего батч спасает. Остановку по `rejected` агент всегда может устроить сам, разбив цепочку.

4. **Поллинг и чтения вне батча.** `Capture` возвращает `initiated` — оверлей поднимается асинхронно, и следующий за ним в батче `OverlaySelect` может прийти раньше, чем оверлей готов: такой сценарий остаётся поллингом (`Capture` → опрос `state` → `OverlaySelect`). `screenshot` вернул бы картинку внутри текстового отчёта батча. Описание `batch` предупреждает об обоих случаях.

5. **Лимит 50 шагов.** Каждый шаг — HTTP-запрос с таймаутом 15 с; патологический батч из тысяч шагов занимал бы главный поток приложения и агента на минуты. Лимит с читаемой ошибкой — одна проверка перед началом исполнения.

## Risks / Trade-offs

- [Батч не транзакционен] → ошибка посреди цепочки оставляет приложение в промежуточном состоянии — но это то же состояние, что после N одиночных вызовов с той же ошибкой; агент видит номера и статусы шагов и реагирует (undo, повтор). Откат исполненных шагов был бы новым поведением, которого нет у пользователя.
- [Окна из батча] → шаги могут открывать окна (`OpenEditor`, `PrefsOpen`) — семантика уже есть у одиночных `action`, батч ничего не добавляет; правило гигиены окон (спрятать после проверки) остаётся на вызывающем.
- [Число инструментов в тесте] → тест `tools_list_has_six_tools` обновляется на семь.

## Migration Plan

Развертывания и миграции нет: `cargo build --release` пересобирает мост `target/release/minisnap-mcp` — ровно тот путь, который `.zcode/config.json` уже регистрирует; новый мост подхватится при следующем старте MCP-сервера (новая сессия ZCode), работающий minisnap не трогается. Откат — реверс коммита.
