# Design

## Context

Композит элементов уже рисуется одной точкой входа: `render::draw_elements` → `draw_element` (`src/editor/render.rs`), и ею же рисуются закоммиченные элементы на канве (`EditorView::draw`) и черновики фигур — машина драга отдаёт готовый `ElementKind` через `preview()`, mouse-up коммитит то же значение в `Command::AddElement`. Расходятся текстовые взаимодействия (ввод рисует `NSTextField`, а фиксация — Core Text `text::draw_text` с ореолом и повторным замером/зажимом), черновик коллаута держит заглушку `text: ""` с якорем в точке основания, а перенос/тяга конца рисуют призрак поверх всех элементов. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**

- Один билдер геометрии на черновик и коммит текстовых элементов: инвариант «preview.kind == commit.kind», проверяемый юнит-тестом.
- Ввод текста виден рендером зафиксированного элемента с первого глифа (шрифт, кегль, цвет, белый ореол, позиция, кламп у краёв).
- Сохранить нынешнюю механику ввода как есть: NSTextField с клавиатурой, IME, выделением, Esc, коммитом по клику мимо — только в роли невидимого прокси.
- Перенос/тяга конца без смены глубины элемента; маркеры следуют за призраком.

**Non-Goals:**

- Полноценный текстовый редактор на канве (свой NSTextInputClient, отрисовка выделения/композиции IME в канве) — переизобретение AppKit ради чистоты.
- Изменение схемы журнала `commands.json` и формата `Command` — новые варианты команд не вводятся.
- Правка шрифта/вида самого текста (орел, кегль по умолчанию, `LINE_HEIGHT_FRACTION`) — рендер как есть, меняется только то, кто его вызывает во время ввода.

## Decisions

### 1. Черновик текста живёт в машине драга (`src/editor/drag.rs`)

Сегодня состояние ввода размазано: цель — `TextTarget` в окне, живая строка — в `NSTextField`, геометрия коммита — в `commit_text_editor` окна. Вводится `TextDraft` в `DragMachine`: цель (origin+color нового / id правки), кегль, живая строка; API `begin_text_draft` / `update_text` / `update_text_size` / `commit_text(elements, image, next_id) -> Option<Command>` / `cancel_text`. Черновик попадает в `preview()` как полный `ElementKind`, построенный функцией `text_draft_kind` (для правки — замена текста в kind элемента): `text::measure_block` → `clamp_block` / `callout_anchor`, те же функции, что использует коммит. Сборка `AddElement` для нового текста уходит из окна в машину — вся геометрия текстовых элементов в одном чистом модуле, как у фигур.

Альтернатива — считать черновик в окне на каждый keystroke и скармливать канве — отклонена: дублировала бы билдер между окном и машиной и не покрывалась бы юнит-тестами без AppKit.

`PendingCallout` получает живую строку: якорь пересчитывается `callout_anchor` на каждый keystroke (сегодня так пересчитывается только рамка поля в `refit_callout_editor`), хвост стрелки через `callout_tail` стоит у края блока с первой буквы. Для пустой строки блок считается каретко-широким — хвост чуть отступает от основания и у первого глифа встаёт к краю реального блока; прыжка в момент Enter нет.

### 2. NSTextField — невидимый прокси ввода (`src/editor_window.rs`)

Поле остаётся машиной ввода, но перестаёт быть дисплеем: цвет текста прозрачный, каретка окрашивается у field editor'а (`insertionPointColor`); рамка поля — прямоугольник черновика блока в координатах вью (тот же перевод, что сегодня), так что каретка сидит на глифах. `controlTextDidChange` → `machine.update_text` + redraw. Выделение и подчёркивание композиции IME остаются полевым хромом (в композит не попадают — поле и так не попадает).

Альтернативы, отклонённые:
- Стилизовать видимое поле под элемент (обводка через `NSStrokeWidthAttributeName`, метрики «как Core Text») — два рендера останутся, пиксельное совпадение недостижимо (нынешняя константа `0.19·font_pt` — калибровка именно этого расхождения); класс багов сохраняется.
- Рисовать каретку в канве по замеру префикса — точнее, но переизобретает выделение/композицию; держим как fallback, если каретку не удастся окрасить независимо от прозрачного текста.

Умирают `TEXT_EDITOR_WIDTH_PT = 200` (минимум ширины видимого поля), порог кегля `.max(9.0)` и геометрическая роль набивки `+12/+6`pt; `0.19·font_pt` понижается до вертикальной подгонки каретки (хром, не контракт).

### 3. Правка существующего: зажим в `apply_cmd::EditText`

Черновик правки рисуется от якоря элемента с живым текстом и клампом по росту; чтобы фиксация не прыгала, `apply_cmd::EditText` (`src/editor/mod.rs`) пересчитывает `clamp_block` для нового текста — тот же прецедент, что уже есть у `SetTextSize` (`clamp_text_block`). Реплей журнала детерминирован (зажим — чистая функция от команды и размера базы), схема `commands.json` не меняется, старые сессии читаются как есть.

### 4. `preview()` возвращает полный список отрисовки

Вместо `Preview { hide, extras }` машина возвращает готовый список элементов для канвы: призрак переноса/тяги замещает элемент на его индексе, черновики дорисовываются в конец. `EditorView::draw` рисует один список через `draw_elements`; прятать редактируемый элемент продолжает окно (фильтр по id правки — единственное, что окно знает про отрисовку). `draw_markers` берёт геометрию выделенного элемента из этого же списка (метод-запрос в машину), а не из документа — маркеры следуют за призраком.

Альтернатива — метка индекса у extras и склейка в окне — отклонена: контракт «окно ничего не знает о порядке» чище у полного списка.

## Risks / Trade-offs

- [Каретку не удастся окрасить независимо от прозрачного текста поля] → fallback: каретка канвы по замеру префикса до insertion point той же Core Text-метрикой (см. решение 2); решение принимается при имплементации задачи окна.
- [`controlTextDidChange` не стреляет на обновлениях IME-композиции] → проверить на живой; если нет — слушать field editor (`textDidChange` NSTextView) напрямую. Черновик в любом случае рисует строку поля целиком.
- [Клик внутри невидимого поля ставит каретку по полевой раскладке, при дрейфе метрик AppKit↔Core Text — считанные пиксели] → допустимо: это хром каретки, глифы от поля больше не зависят.
- [Канва клипает содержимое прямоугольником кадра — растущий у края текст без клампа был бы обрезан] → кламп на каждый keystroke уже часть дизайна (не риск, а следствие).

## Migration Plan

Единый коммит с живой проверкой через minisnap MCP (`scripts/build_app.sh release`, перезапуск экземпляра по PID). Откат — revert коммита; журнал сессий и PNG-композит совместимы в обе стороны (ни формат команд, ни вывод не меняются).
