# Proposal

## Why

При повторном запуске режима заморозки (второй и далее снимок за жизнь процесса) на экран на мгновение мелькает кадр прошлого снимка. Причина: окно и слои оверлея переиспользуются, в слое кадра после завершения режима остаётся прежнее T0-изображение, а подмена содержимого в `OverlayView::show` выполняется без отключения неявных анимаций Core Animation — `contents` слоя анимируется кроссфейдом ~0.25 с, и пользователь видит «старый кадр → новый» вместо мгновенного показа нового. При первом снимке дефекта нет: старое содержимое слоя пустое.

## What Changes

- Подмена содержимого слоя кадра (`frame_layer.setContents`) в `OverlayView::show` выполняется внутри `CATransaction` с отключёнными action'ами — как уже сделано для затемнения, HUD и рамки. Новый T0-кадр появляется на экране в момент показа окна, без кроссфейда.
- `finish` не меняется: кадр должен «доживать» на экране во время fade-out рамки — это существующее поведение по дизайну.
- Доменный скилл `minisnap-capture` обновляется: инвариант «обновления слоёв внутри транзакции с отключёнными action'ами» распространяется на слой кадра при показе.

## Capabilities

### New Capabilities

- (нет)

### Modified Capabilities

- `frozen-capture`: требование «Полноэкранный overlay» дополняется сценарием — при показе оверлея повторного запуска на экране не появляется кадр прошлого снимка; показанный кадр соответствует моменту T0 текущего запуска с первого кадра анимации.

## Impact

- `src/overlay.rs`: точечная правка в `OverlayView::show` (обёртка `setContents` в `CATransaction` с `setDisableActions(true)`); остальной поток показа — состояние, вуали, рамка, активация окна — без изменений.
- `.zcode/skills/minisnap-capture/SKILL.md`: строка инварианта про анимации слоёв.
- `src/capture.rs`, `src/app.rs`, вывод результата и редактор не затрагиваются. Change не пересекается с начатым `overlay-follows-cursor` (тот меняет набор кадров T0 и переключение дисплеев, этот — момент подмены содержимого слоя при показе).
