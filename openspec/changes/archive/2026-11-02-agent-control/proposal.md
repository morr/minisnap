# Proposal

## Why

Сессии, тестирующие minisnap вживую, каждый раз строят взаимодействие с приложением из подручных средств: Swift-драйверы на CGEvent в /tmp, `screencapture` с подбором флагов и дисплеев, `osascript` по меню трея, пиксельный скан цветов в PNG. Это ломается стабильно: синтетические клики молча не доходят, скриншоты ловят чужой Space или конвертируют цвета, окна путаются между инстансами, состояние приложения (какой инструмент активен, что выделено, значение слайдера) добывается «археологией» по пикселям вместо запроса. Ровно этот класс проблем решён в проекте qwe через BRP — встроенный в приложение HTTP-сервер, которому можно программно сказать «что сделать» и у которого можно запросить состояние. minisnap нужен свой аналог такого канала, обёрнутый в MCP, чтобы агент работал с приложением штатными инструментами, а не одноразовыми скриптами.

## What Changes

- Приложение поднимает встроенный **agent-сервер**: HTTP на `127.0.0.1` (дефолтный порт, переопределяется конфигом и `MINISNAP_AGENT_PORT`), обслуживающий запросы из отдельного потока и исполняющий их в главном потоке через существующий насос `MainJob`/`tick`. Никакого AppleScript и синтетического ввода: каждое действие — вызов существующего кодового пути приложения (тот же метод, что у пункта меню, хоткея или обработчика мыши).
- Сервер отвечает идентичностью экземпляра (pid, путь к исполняемому файлу, checkout-метка) в каждом ответе — путаница двух запущенных копий исключается проверкой, а не осторожностью.
- `GET /state` — полное состояние: что открыто (редактор, оверлей, prefs), кадры собственных окон, документ редактора (элементы с геометрией, выделение, инструмент, цвет, толщина, undo/redo, файл), конфиг (хоткеи, save_dir, retention).
- `POST /action` — действия уровня приложения: запустить захват (с редактором и без), открыть последний снимок/заданный файл, закрыть редактор, программно завершить оверлей выделением заданного прямоугольника (эквивалент протяжки), открыть/закрыть prefs, выйти.
- `POST /editor` — операции редактора: выбрать инструмент, цвет, толщину, применить команду журнала, undo/redo, выделить элемент, листинг к соседнему снимку. Всё через `OpenShot::apply` и тот же sync-путь, что и мышиные обработчики.
- `GET /screenshot` — снимки без участия экрана: композит документа (чистый `render_composite`, детерминированный, без Space и цветовых конверсий `screencapture`) и снимок окна редактора рендерингом его view-иерархии.
- `GET /log` — кольцевой буфер строк журнала приложения: переходы состояния видны запросом, а не чтением stderr запуска.
- Приложение регистрирует себя в файле-реестре экземпляров (pid, порт, exe, метка, время старта) и снимает запись при выходе — MCP находит инстансы без сканирования портов.
- Новый бинарник **`minisnap-mcp`** — MCP-сервер stdio: находит живые инстансы по реестру с проверкой идентичности, оборачивает endpoint'ы сервера в инструменты (`instances`, `state`, `screenshot` с картинкой в ответе, `action`, `editor`, `log`), печатает человекочитаемые ответы и не бросает исключений на мёртвом приложении.
- Не входит в объём: управление prefs-рекордером хоткеев программным вводом клавиш, драг элементов перетаскиванием координат (достаточно команд журнала), захват произвольных окон других приложений.

## Capabilities

### New Capabilities

- `agent-control`: встроенный agent-сервер приложения и MCP-обёртка `minisnap-mcp` — программное управление запущенным minisnap и запрос его состояния без AppleScript и синтетического ввода.

## Impact

- `src/agent_server.rs` (новый) — HTTP-сервер, разбор запросов, реестр экземпляров.
- `src/agent_proto.rs` (новый) — сериализуемые типы запросов/ответов, общие для приложения и MCP-бинарника.
- `src/logbuf.rs` (новый) — кольцевой буфер журнала.
- `src/app.rs` — новый вариант `MainJob::Agent`, диспетчер запросов в главном потоке, запуск сервера при старте.
- `src/editor_window.rs` — публичные методы состояния и операций (инструмент, цвет, толщина, команда, undo/redo, выделение, листинг, снимок окна).
- `src/overlay.rs` — программное завершение выделением заданного прямоугольника.
- `Cargo.toml`, `src/bin/minisnap-mcp.rs` (новый) — второй бинарник.
- `openspec/specs/agent-control/spec.md` — новая спека.
- Скилл `minisnap-architecture` — строка нового модуля; `minisnap-shell` — механизм сервера; новый скилл или секция про live-тестирование через MCP вместо скриптов.
