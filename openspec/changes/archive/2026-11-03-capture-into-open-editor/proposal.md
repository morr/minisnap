# Proposal

## Why

Обычный захват (`⌘⌥4`) и захват с редактированием (`⌘⌥5`) уже идут по одному пайплайну вывода, но при `⌘⌥4` снимок никогда не попадает в редактор: если окно редактора открыто, оно продолжает показывать старый снимок, и свежий приходится искать листанием или через `⌘⌥0`. Осмысленное отличие `⌘⌥4` от `⌘⌥5` должно быть одно — не открывать редактор, если тот не был открыт; во всём остальном действия идентичны.

## What Changes

- Обычный захват: если окно редактора в момент завершения выделения открыто (видно на экране), новый снимок показывается в нём так же, как при «capture and edit» — тем же путём: документ заменяется новым снимком, окно выходит на передний план.
- Если окно редактора не открыто (ни разу не открывалось в этом запуске либо закрыто/спрятано), обычный захват, как и раньше, его не открывает и не поднимает.
- Пайплайн вывода (кроп, звук затвора, буфер обмена, сохранение файла, ретенция) не меняется — он уже общий для обоих действий.
- Поведение пункта меню «захват» и агентского действия `Capture { edit: false }` меняется синхронно с хоткеем — все они идут через один кодовый путь.

### Modified Capabilities

- `shot-editor`: требование «Режим захвата с редактированием» — обычный захват при открытом окне редактора показывает в нём новый снимок (как «capture and edit»); при не открытом окне редактор по-прежнему не открывается.

## Impact

- `src/app.rs`: решение «показывать ли снимок в редакторе» переезжает в обработку `MainJob::OpenEditor` в `tick:` — обычный захват отправляет ту же задачу с условием «окно редактора видно», «capture and edit» — без условия; колбэк `OverlayOutcome::Selected` в `capture_ready` передаёт это условие.
- `src/agent_proto.rs` не меняется: действие `Capture { edit }` сохраняет форму; меняется только его эффект.
- Спеки: меняется только `shot-editor`; `capture-output` (буфер, файл, ретенция, звук) и `global-hotkeys` остаются без изменений.
