# Design

## Context

Оба действия захвата уже идут по одному пути: `start_capture(edit)` → `MainJob::CaptureReady { result, edit }` → `capture_ready` → оверлей; в колбэке `OverlayOutcome::Selected` — кроп, звук затвора, буфер, сохранение; при `edit == true` в `jobs_tx` уходит `MainJob::OpenEditor { path }`, и `tick:` вызывает `open_editor` — новый снимок в единственном переиспользуемом окне плюс отложенный вывод на передний план (`editorWindowToFront:`). При `edit == false` задача не отправляется вовсе, и даже открытое окно редактора продолжает показывать старый снимок.

Окно редактора живёт в `AppController.editor` (`RefCell<Option<EditorWindow>>`): создаётся лениво при первом открытии и переживает закрытие. Закрытие (⌘Q/⌘W/Esc, жёлтая кнопка, агентский `CloseEditor`) прячет окно `orderOut`'ом — `miniaturize:` и `performMiniaturize:` переопределены в `editor_window.rs` на `orderOut`, потому что у accessory-приложения нет дока. Видимость окна — `window.isVisible()`: тот же предикат, что `agent_window_info` уже сообщает в агентском `state`.

Колбэк `Selected` — `Box<dyn FnOnce>`, захватывающий только клоны (`save_dir`, `retention`, `jobs_tx`); доступа к контроллеру у него нет.

## Goals / Non-Goals

**Goals:**
- Единый хвост пайплайна: решение «показывать ли снимок в редакторе» — одно условие на общем пути, а не развилка двух пайплайнов.
- Проверка состояния окна в момент, максимально близкий к показу снимка, на главном потоке.

**Non-Goals:**
- Не менять пайплайн вывода (кроп, звук, буфер, сохранение, ретенция) — он уже общий.
- Не менять протокол агента: `Capture { edit }` сохраняет форму, меняется только эффект `edit: false`.
- Не трогать семантику `⌘⌥5`, `⌘⌥0` и пунктов меню.
- Не вводить настройку для нового поведения.

## Decisions

1. **Условие едет в задаче, а не вычисляется заранее.** `MainJob::OpenEditor` получает поле `only_if_visible: bool`: «capture and edit» шлёт `false`, обычный захват — `true`. Обработчик в `tick:` при `only_if_visible == true` и невидимом окне редактора пропускает задачу со строкой в журнале. Альтернативы: решить в `capture_ready` до `overlay.show` — решение замораживается на всю сессию выделения, которая может длиться сколько угодно, а состояние окна за это время меняется; отдать колбэку слабую ссылку на контроллер — расширяет захваты замыкания и всё равно фиксирует момент решения на момент выделения. Проверка в `tick:` — самый поздний из возможных моментов, на главном потоке, рядом с ivar'ом `editor`.

2. **Предикат «редактор открыт» — объект существует и `window.isVisible()`.** `orderOut`-пути закрытия дают `isVisible() == false` и для ⌘Q-закрытия, и для жёлтой кнопки, поэтому ни то ни другое окно не поднимет. Тот же предикат уже сообщает `agent_window_info`, так что «виден ли редактор» значит одно и то же для пользователя, хоткея и агента; отдельный учёт `isMiniaturized` не нужен — миниатюризация здесь и есть `orderOut`.

3. **Показ снимка — тот же `open_editor`, без отдельной «тихой» ветки.** При видимом окне обычный захват делает ровно то же, что «capture and edit»: `show_shot` нового снимка плюс отложенный вывод окна на передний план. Идентичность действий — норматив дельты; единственная разница — само условие отправки.

4. **Меню и агент наследуют поведение автоматически.** Пункт меню «захват» и `agent_capture(edit)` зовут тот же `start_capture(edit)`; спека `agent-control` требует исполнения «теми же кодовыми путями, что и меню и хоткеи», так что отдельные ветки для этих входов не вводятся.

## Risks / Trade-offs

- [Гон: окно закрыли между завершением выделения и обработкой задачи (тиковый зазор)] → проверка выполняется в момент обработки — окно не поднимется; снимок и так уже в буфере и файле. Обратный гон (окно открыли во время сессии выделения, например `⌘⌥0`) покажет снимок в только что открытом редакторе — это соответствует «идентично 5».
- [`MainJob::OpenEditor` меняет форму] → `MainJob` — внутренний тип `app.rs`, в протоколе `agent_proto` его нет, мост `minisnap-mcp` его не читает; меняются только конструкторы задачи в `app.rs` (колбэк захвата и debug-хук `MINISNAP_DEBUG_OPEN_EDITOR`).

## Migration Plan

Развертывания и миграции данных нет: пересборка бандла `scripts/build_app.sh release` и перезапуск. Откат — реверс коммита.

## Open Questions

Нет: трактовка «открыт» как «окно видно на экране» зафиксирована решением 2, поведение гон — решением 1.
