# Proposal

## Why

Сейчас в окне редактора видна только красная системная кнопка — миниатюризация и зум скрыты. Пользователь ожидает стандартный хром macOS: все три кружка на месте и живые. Отдельная кастомная кнопка закрытия не нужна — красная уже работает. Жёлтая кнопка не может быть обычной миниатюризацией: приложение accessory без иконки в доке, миниатюризированное окно было бы недостижимо — вместо неё окно прячется и возвращается следующим открытием снимка.

## What Changes

- Все три системные кнопки (traffic-lights) видимы и работоспособны: close закрывает окно (как сейчас), зелёная разворачивает окно на весь экран и возвращает из него, жёлтая прячет окно (не миниатюризирует в док).
- Спрятанное окно возвращается любым повторным открытием снимка: захват с редактированием или «открыть последний» (`show_shot` уже делает `makeKeyAndOrderFront` для спрятанного окна).
- Кнопки должны быть включены на уровне окна: без битов `Miniaturizable`/`Resizable` в маске стиля AppKit рисует их выключенными независимо от действий.
- Известное ограничение macOS 26 (Tahoe): traffic-lights игнорируют override `setTarget:`/`setAction:` у `standardWindowButton` (проверено в change `editor-zcode-ui`: действия не срабатывают). Поведение навешивается на подкласс окна — перехват методов `zoom:` и `performMiniaturize:`, которые система вызывает у окна; механизм подтверждается реальными кликами в задачах.

### Modified Capabilities

- `shot-editor`: требование «Окно редактора» — вместо скрытых миниатюризации и зума: три живые системные кнопки, зелёная — полный экран, жёлтая — спрятать окно с возвратом через повторное открытие снимка.

## Impact

- Код: `src/editor_window.rs` — маска стиля окна (без бита `FullScreen`: окно с ним теряет системное закругление углов), перехват `zoom:`/`performMiniaturize:` на `KeyableWindow`.
- Поведение зелёной кнопки: если на macOS 26 полный экран не включается без бита `FullScreen` в маске (ломает закругление), зелёной кнопкой остаётся стандартный зум-максимизация (`zoom:` без перехвата) — решение фиксируется в tasks/design по результатам проверки.
- Спека: `openspec/specs/shot-editor/spec.md` — дельта по требованию «Окно редактора».
- Change `editor-zcode-ui` идёт параллельно и меняет то же требование (светлая полоса, карточка, без имени файла) — при архивации одного из них дельту второго необходимо пересобрать.
