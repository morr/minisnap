# Design

## Context

Живая проверка `upload-to-artifacts` показала: прямой HTTPS до
`artifacts.spacehubstore.com` из России рвётся («upload failed - connection lost»,
РКН-троттлинг). У пользователя уже работает локальная цепочка: privoxy на
`127.0.0.1:8118` (HTTP-прокси) форвардит в SOCKS туннеля `ssh -4 -D 5555`. Сетевого
крейта в проекте нет — транспорт загрузки построен на `NSURLSession`
(`uploadTask` + `connectionProxyDictionary`), и системный стек прокси — тот же
механизм, которым NSURLSession ходит через HTTP/SOCKS-прокси без новых зависимостей.

## Goals / Non-Goals

**Goals:** прокси как строковая настройка провайдера Artifacts (конфиг + поле в
настройках наравне с токеном и проектом); разбор `scheme://host:port` без новых
зависимостей; применение без перезапуска (поле живёт в общем потоке
`upload_fields_changed`).

**Non-Goals:**
- Аутентификация на прокси (локальный privoxy без пароля; `scheme://user:pass@host`
  не поддерживается).
- PAC-скрипты, auto-proxy-discovery, настройка системных прокси — прокси только
  для загрузки minisnap.
- Прокси для других исходящих соединений (звук, агент-сервер, обновления) — только
  запросы провайдера загрузки.
- Отдельная валидация схемы с алертом: неразбираемая строка ведёт себя как пустая
  (напрямую) — поведение фиксируется тестом, отдельного UI-ошибки нет.

## Decisions

### Значение и место: строка `proxy` в секции провайдера, третье поле настроек
`ArtifactsProviderConfig` получает `proxy: String` (TOML-ключ `proxy`, дефолт — пустая
строка: прямое соединение). Альтернатива — отдельная секция `[upload.proxy]` или
глобальный прокси приложения: отклонены — прокси принадлежит провайдеру (у будущего
провайдера свой адрес/цепочка) и в v1 это одна строка, секция избыточна. В prefs поле
добавляется записью в реестр полей провайдера (`FieldKey::Proxy` + строка «Proxy») —
раскладка, высота окна и сохранение достаются из существующего механизма полей, новая
UI-ветка не пишется.

### Транспорт: `connectionProxyDictionary` из строковых ключей CFNetwork
Разбор — чистая функция `parse_proxy(&str) -> Option<ProxySettings>` (scheme, host,
port; тесты на матрицу: http, https, socks5, socks5h, без порта, мусор, пусто, порт
вне диапазона). Порт обязателен: без него строка не разбирается (типовые локальные
прокси всегда с портом; молчаливый дефолт 80/1080 — источник тихих недиагностируемых
падений). Неразбираемая строка = пустой словарь → прямое соединение (и запись в
журнал при построении бекенда — один раз на создание, не на каждый запрос).

`ArtifactsBackend` хранит `Option<ProxySettings>`; при построении сессии
`NSURLSessionConfiguration::defaultSessionConfiguration()` получает
`setConnectionProxyDictionary` с записями:
- `http`/`https`: `kCFNetworkProxiesHTTPEnable/HTTPProxy/HTTPPort` плюс
  `kCFNetworkProxiesHTTPSEnable/HTTPSProxy/HTTPSPort` на один host:port —
  CONNECT-туннель для HTTPS через HTTP-прокси, путь, которым ходит privoxy
  (проверенный маршрут пользователя).
- `socks5`/`socks5h`: `kCFNetworkProxiesSOCKSEnable/SOCKSProxy/SOCKSPort` —
  best effort: поддержка SOCKS в NSURLSession через словарь неполная в некоторых
  версиях macOS; документированный надёжный путь — HTTP-фронт (privoxy) перед SSH-SOCKS,
  он и заполняется пользователю.
- Пустая настройка: словарь не задаётся вовсе (`nil`) — сессия, как и сейчас,
  наследует системные прокси. Альтернатива «пустой словарь = отключить системные
  прокси» отклонена: тихо меняет поведение тех, у кого системный прокси настроен.
- Ключи словаря — значения CFNetwork-констант, системные имена сущностей прокси
  (`"HTTPEnable"`, `"HTTPProxy"`, `"HTTPPort"`, `"HTTPSEnable"`, `"HTTPSProxy"`,
  `"HTTPSPort"`, `"SOCKSEnable"`, `"SOCKSProxy"`, `"SOCKSPort"`). Литеральные имена
  констант (`"kCFNetworkProxiesHTTPEnable"`) — неизвестные словарю ключи: NSURLSession
  молча игнорирует их и ходит напрямую (ловится только живым прогоном: соединение
  процесса идёт мимо 8118). В objc2-foundation этих констант нет, тянуть
  CFNetwork-крейт ради них не нужно; значения — `NSNumber` (bool/int) и `NSString`.

Применение без перезапуска: бекенд строится на каждую загрузку заново
(`build_backend`), прокси читается из конфига в тот же момент, что и токен.

### Заполнение конфига пользователя
После применения: `proxy = "http://127.0.0.1:8118"` в `[upload.artifacts]` конфига
(правка файла при выключенном приложении, как с токеном). Живая проверка
`upload-to-artifacts` (6.1–6.2) продолжается поверх этого change'а: кнопка Upload,
⌘⌥6, диалог «не настроено» и алерт ошибки — теперь через прокси.

## Risks / Trade-offs
- SOCKS через `connectionProxyDictionary` может не сработать на части версий macOS —
  явно документировано, надёжный путь пользователя (privoxy-фронт) не зависит от этого.
- Неразбираемая строка молча идёт напрямую — компромисс против алерта на каждый
  keystroke поля; журнал при создании бекенда даёт след («proxy setting ignored: …»).
