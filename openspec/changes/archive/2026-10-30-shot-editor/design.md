# Design

## Context

Проект уже умеет: захват T0 → оверлей выделения → кроп → буфер + тихий PNG в `~/Pictures/minisnap` (`app.rs`, `capture.rs`, `overlay.rs`, `output.rs`), глобальные хоткеи и меню (`hotkeys.rs`, `app.rs`), окно настроек в два ряда (`prefs.rs`, в работе). Технологический стек чистый objc2 без внешних UI-фреймворков; motivation — см. proposal.md.

## Goals / Non-Goals

**Goals:**
- Одно переиспользуемое окно редактора с рендером «кадр + векторные элементы» и честным undo/redo через журнал команд.
- Автосохранение файла после каждой команды; сессия (оригинал + команды) в `/tmp/.minisnap/` для восстановления истории.
- Интеграция с существующими механизмами: меню, хоткеи, prefs, `shot_files_oldest_first` для листания.

**Non-Goals:**
- Upload на artifacts-сервер (следующий change: кнопка Upload, ⌘⌥6, токен/проект).
- Зум холста, переименование файла из заголовка, системный color picker, выбор/перенос области блюра как «элемента с концами» (блюр — область с маркерами углов, достаточно переноса).

## Decisions

**Рендер: один custom NSView, отрисовка в CGContext; не CALayer-на-элемент и не WKWebView.**
Композит (базовый кадр + элементы + рамки выделения) перерисовывается целиком на каждое изменение. Альтернативы: WKWebView с canvas — отвергнуто (лишний процесс и WebKit-мост против философии проекта); CAShapeLayer/CATextLayer на элемент — отвергнуто (хит-тест, z-порядок и ретинизация сложнее, чем один проход CGContext; слои уже опробованы в `overlay.rs` для других задач). Паттерн окна и обработка мыши — как в `overlay.rs` (`define_class`, `NSResponder`), но окно обычного уровня с титульной строкой, не full-screen.

**Модель документа: состояние + журнал команд, undo = перепроигрывание префикса.**
Рабочее состояние — `{ base: CGImage, elements: Vec<Element> }`; журнал `Vec<Command>`. Команда — детерминированная мутация состояния: `AddElement`, `DeleteElement(id)`, `MoveElement(id, Δ)`, `MovePoint(id, конец, точка)`, `EditText(id, текст)`, `Recolor(id, цвет)`, `Crop(rect)`, `Resize(размер)`. `Crop`/`Resize` мутируют `base` и трансформируют координаты уже существующих элементов. Undo откусывает последнюю команду и rebuild-ит состояние перепроигрыванием префикса от оригинала — никаких обратных операций и рассинхронизации. Во время drag'а элемент мутируется живьём, команда фиксируется на mouse-up.

**Элементы — enum, координаты в пикселях изображения.**
`Arrow { a, b, color, width }` (древко постоянной толщины с плоским началом + сплошной треугольный наконечник в B), `Rect`, `Line`, `Pen { points }`, `Text { origin, text, color, size }` (многострочный, разделитель `\n`), `Callout { tip, tail, text, color, size }` (стрелка от основания к острию; позиция текста вычисляется у основания с зажатием в границы кадра), `Blur { rect }`. Идентификатор элемента — монотонный `u64`, а не индекс: журнал остаётся валидным после удалений. Хит-тест — по геометрии с допуском (расстояние до отрезка/контура, bbox для текста/блюра).

**Текст: Core Text в CGContext (новая зависимость `objc2-core-text`).**
Рендер композита идёт в CGContext, а AppKit-рисование текста туда не пробрасывается — берём CTLine/CTFrame. Белая обводка — два прохода: stroke-атрибут, затем заливка. Текст многострочный: строки `\n` рисуются построчно. Редактирование на месте — field editor окна (NSText), позиционируемый над элементом. Клавиши ввода перехватываются явно через `control(_:textView:doCommandBy:)`: Enter фиксирует (`EditText`/`AddElement`), Shift+Enter вставляет перенос, Esc отменяет ввод. Полагаться на `controlTextDidEndEditing` как на единственную точку фиксации нельзя — на Enter в этом окне оно не приходит (проявилось как «белый дубль» текста: элемент не создавался, поле редактора зависало на экране); уведомление остаётся fallback'ом для клика в сторону.

**Блюр-пикселизация без CoreImage.**
Регион `base` уменьшается в маленький CGBitmapContext и рисуется обратно растянутым с `interpolation = none` — мозаика. Пересчитывается от `base` при каждой отрисовке, поэтому перенос региона открывает оригинал под ним.

**Сессия в `/tmp/.minisnap/<имя файла без .png>/`.**
`original.png` (сырой кроп) + `commands.json` (serde уже в deps). Запись: композит → PNG в `save_dir` атомарно (tmp+rename), `commands.json` переписывается целиком. Retention — 50 каталогов по mtime. Открытие снимка: есть сессия — original + replay; нет — файл становится оригиналом новой сессии. Деградация при очистке `/tmp` заложена в спеку.

**Кнопки и тулбар: NSStackView + NSButton с SF Symbols** (`arrow.up.right`, `rectangle`, `line.diagonal`, `scribble`, `textformat`, `drop`/`blur`, `crop`, `square.and.arrow.up` позднее для Upload), для коллаута — кастомная иконка «стрелка + текст»; пресеты цвета — поповер из 9 цветов (с белым), слайдер толщины — NSSlider. Кнопки ◄/► (`chevron.left`/`chevron.right`) — в левой верхней части над холстом. Применение кропа/ресайза — кнопка OK возле рамки (как на референсе), Enter дублирует, Esc отменяет.

**Окно и активация.**
Одно окно живёт в `AppController` (`RefCell<Option<EditorWindow>>`, как prefs). Активация accessory-приложения — по отработанной схеме prefs: `activate()` + `activateIgnoringOtherApps` + отложенный `makeKeyAndOrderFront` одноразовым таймером. Размер окна = размер кадра, ограниченный `visibleFrame` экрана; крупный кадр ужимается, рендер остаётся в пикселях изображения (hit-test и рендер — в координатах изображения, конверсия по масштабу view).

**Конфиг: третье поле `capture_edit_hotkey`, дефолты `⌘⌥4` / `⌘⌥5` / `⌘⌥0`.**
Миграция существующего конфига: если `capture_edit_hotkey` отсутствует, а `capture_hotkey` равен старому дефолту `⌘⌥5`, при загрузке capture сдвигается на `⌘⌥4`, а `⌘⌥5` отдаётся новому действию (записывается в файл). Пользовательские комбинации не трогаются. Меню получает пункт «Capture and Edit» с keyEquivalent; prefs — третью строку (новый тег рядом с `ROW_CAPTURE`/`ROW_OPEN_LATEST`).

## Risks / Trade-offs

- [Полный перерендер композита на каждый mouse-move на Retina-кадре] → CG-отрисовка дешёвая, кадры обычно ≤ 5K×3K; если замер покажет лаг — кэшировать статичную часть (base + применённые элементы) и перерисовывать только активный элемент. Решение по факту замера, на архитектуру не влияет.
- [Core Text — новый мост в deps] → минимальная по объёму familly-обвязка objc2; без неё текст в CGContext не нарисовать штатно.
- [Undo через replay на длинном журнале] → журнал за сессию — десятки команд, replay дешевле обратных операций и не может разойтись с состоянием.
- [`/tmp` очищается при перезагрузке] → история правок старых снимков теряется, файл остаётся; поведение специфицировано как деградация, не бага.
- [Изменение дефолта захвата ломает привычку ⌘⌥5] → одноразовая миграция сдвигает старый дефолт на ⌘⌥4, пользовательские комбинации не трогаются.

## Migration Plan

Зелёное поле без деплоя: применение change'а — обычная задача apply. Единственная миграция данных — одноразовый сдвиг дефолта хоткея в `config.toml`, описан в Decisions. Откат — git revert, конфиг пользователя при этом правится вручную.
