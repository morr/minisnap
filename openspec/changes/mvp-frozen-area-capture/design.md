# Design

## Context

Проект greenfield: кода нет, стек выбирается этим change. Платформа — macOS 15+ (Apple Silicon), из системных API доступны ScreenCaptureKit (включая `SCScreenshotManager`, macOS 14+) и современный AppKit. Все продуктовые решения зафиксированы в proposal и спеках; здесь — как их строить. Ключевая механика продукта — «заморозка»: снимок дисплея и список видимых окон фиксируются в один момент T0, всё дальнейшее взаимодействие идёт с этим кадром.

## Goals / Non-Goals

**Goals:**

- Один процесс, нативный UI без GUI-фреймворков, минимальная латентность хоткей→оверлей.
- Пиксельная точность на Retina (2x) — кроп без смещений и размытия.
- Только одно системное разрешение — Screen Recording; Accessibility не запрашивать.

**Non-Goals:**

- Аннотации/редактор, drag-out, загрузки, звук, автозапуск при входе (SMAppService) — вне MVP.
- Захват нескольких дисплеев за один режим; запись видео; внутриигровые GPU-захваты.
- Кроссплатформенность: код целится только в macOS.

## Decisions

### D1. Стек: чистый AppKit через objc2, без GUI-фреймворка

Оверлей, tray и prefs — это AppKit. Критерий выбора — соответствие механики оверлея возможностям стека:

| Вариант | Почему нет |
|---|---|
| winit + egui/wgpu | Полный рендер 5K-фреймбуфера на каждый mouse move; мультидисплейные fullscreen-окна, курсор, scale factor — трение везде |
| Tauri/webview | Латентность холодного старта webview — сотни ms; тяжело для «мигнуть оверлеем» |
| Swift-хелпер + Rust-ядро | Два тулчейна и RPC между ними дороже неудобства objc2 при объёме UI в ~2 окна |

Оверлей ложится на CoreAnimation без единого полного ререндера (см. D5). Цена решения — многословный Rust с `unsafe`-обёртками objc2; оплата — модуль-фасад с узкими безопасными API (см. D8).

### D2. Процесс и оболочка

Один процесс, `NSApplication` с `.accessory` activation policy; в Info.plist бандла — `LSUIElement = true` (без Dock-иконки). Tray — `NSStatusItem` напрямую, не crate `tray-icon`: нужен рендер пункта меню с серым выровненным вправо хоткеем — это бесплатный `NSMenuItem.keyEquivalent`, который заодно отображает модификаторы системными глифами (⌥⌘5). Меню строится из того же конфига хоткеев, что и регистрация — один источник правды.

### D3. Захват и список окон — ScreenCaptureKit

- Снимок: `SCScreenshotManager.captureImage(contentFilter:…)` — одноразовый снимок без поднятия стрима; фильтр по одному дисплею. `CGDisplayCreateImage` не трогаем (deprecated).
- Окна: `SCShareableContent.current` → `windows` — даёт frame (в поинтах), layer, owningApplication, isOnScreen в z-порядке. Для клика-по-окну берём окна с `layer == 0` (нормальные), исключаем свой PID; первый фронт-ту-бэк прямоугольник, содержащий точку клика, — цель.
- Оба вызова выполняются в момент T0, до показа оверлея; их результаты — единственная реальность режима.

### D4. Горячий путь хоткея и дисплей с курсором

```
хоткей (main thread)
  -> NSEvent.mouseLocation -> NSScreen, содержащий точку (фолбэк: main screen)
  -> SCScreenshotManager (пиксели дисплея) + SCShareableContent (окна)   } T0
  -> overlay-окно: заранее создано и спрятано при старте приложения
     setFrame на дисплей, кадр в layer.contents, orderFront
```

Overlay-окно одно и переиспользуемое: дорогое создание `NSWindow` вынесено на старт приложения, в горячем пути остаются только захват (~30–150 ms, зависит от разрешения) и `orderFront` (<20 ms). Уровень окна — `CGShieldingWindowLevel`/`.screenSaver`: поверх всего, включая строку меню.

### D5. Рендер оверлея на статичных CALayer-ах

| Элемент | Слой | Перерисовка |
|---|---|---|
| Кадр T0 | `CALayer.contents` (CGImage) | никогда |
| Затемнение с «дыркой» | `CALayer` чёрный alpha≈0.4 + `CAShapeLayer`-маска с path выделения | только path при mouse move (дёшево) |
| Красная рамка 4pt | `CAShapeLayer` stroke по периметру + `CABasicAnimation` пульса (idle) | никогда (анимация на GPU) |
| Осевые линии-перекрестие (как на макете) | два тонких `CAShapeLayer` через весь экран | position при mouse move |
| Лупа | маленький `CALayer.contents` — сэмпл битмапа вокруг курсора, nearest-neighbor, сетка+перекрестие сверху | при mouse move |
| Размер «WxH» | `CATextLayer` рядом с лупой | строка при mouse move |

Сэмпл лупы — прямо из битмапа T0 (в памяти лежит CGImage), зум ~8–10x. Ничего из перечисленного физически не может попасть в снимок: кроп делается из T0-битмапа, слои существуют поверх него.

### D6. Машина состояний и события

```
idle ── mouse down ──> drag ── mouse up ─> done: кроп -> clipboard+файл -> close
  │                       │
  │ click (down+up без    │ курсор за краем: rect clamp к границам дисплея;
  │ движения)             │ события всего drag-цикла доезжают view,
  v                       │ где был mouseDown (гарантия AppKit)
window capture: rect      │
окна из списка T0         │
  │                       ├── esc (любой момент) ──> cancel: close
  └─ клик мимо окон ──> весь дисплей
```

Клик = down+up в одной точке (допуск ~3pt на дрожь). Esc — `keyDown` у first responder оверлея. На остальных дисплеях — вуаль: пустые окна того же уровня с полупрозрачным фоном, клик = cancel.

### D7. Координаты, Retina, вывод

- `SCWindow.frame` — в поинтах, битмап — в пикселях с `backingScaleFactor` дисплея. Единственный конвертер точка→пиксель (`ScreenGeometry`) с юнит-тестами: это первое, что ломается в таких утилитах. Кроп — `CGImage.cropping(to:)` в пиксельном пространстве, округление вниз/вверх по краям.
- Буфер: `NSPasteboard` c типами PNG (+TIFF для старых приложений).
- Файл: `~/Pictures/minisnap/MiniSnap YYYY-MM-DD HH-MM-SS.png`; при коллизии секунды дополнительно нумеруются. Ретенция 100: при записи чистим только файлы своего паттерна имени — чужие файлы в папке не трогаем.
- PNG-энкод — ImageIO (`CGImageDestination`), без отдельной image-библиотеки.

### D8. Хоткеи и конфиг

- Регистрация — crate `global-hotkey` (под капотом Carbon `RegisterEventHotKey`, тот же путь, что у Tauri); события прилетают на main thread, диспетчеризация по action id.
- Хранение — keycode + модификаторы в `~/Library/Application Support/minisnap/config.toml` (serde): два хоткея, папка снимков, ретенция. Конфиг создаётся с дефолтами при первом запуске.
- Prefs-окно: кодом, без xib — `NSWindow` + `NSStackView`, две строки-рекордера; запись через локальный event monitor; рендер комбинации в свои поля — своя функция в системном порядке глифов (⌃⌥⇧⌘), в меню рендерит сам AppKit.

### D9. Разрешение Screen Recording

Префлайт при старте (`CGPreflightScreenCaptureAccess`); нет — диалог-объяснение + `CGRequestScreenCaptureAccess`/переход в System Settings. Повторная проверка — при `applicationDidBecomeActive` (пользователь вернулся из настроек) и перед каждым запуском режима. Без разрешения хоткей показывает диалог, режим не стартует. Accessibility не требуется нигде: Carbon-хоткеи и чтение bounds окон живут без него.

### D10. Модули кода

```
minisnap (bin)
├── app        NSApplication, run loop, tray, меню, активация режима
├── hotkeys    регистрация, рекордер, рендер глифов
├── capture    SCShareableContent, SCScreenshotManager, ScreenGeometry
├── overlay    окно(а), слои, машина состояний, вуаль
├── output     clipboard, ImageIO PNG, файлы, ретенция
├── prefs      окно настроек
├── permission префлайт и диалоги TCC
└── config     загрузка/сохранение config.toml
```

Крейты: `objc2`, `objc2-app-kit`, `objc2-foundation`, `objc2-screen-capture-kit`, `global-hotkey`, `serde`, `toml`, `dirs`.

## Risks / Trade-offs

- [objc2: многословность и `unsafe`-поверхность] → узкие безопасные фасады по модулям; unsafe не выходит за пределы модуля-владельца вызова.
- [Латентность захвата 30–150 ms на 5K] → переиспользуемое окно и слои без перерендера; если мало — warm-up захвата после старта (запасной ход, не планируем).
- [Смена конфигурации дисплеев во время режима (подключили/отключили монитор)] → подписка на `NSApplication.didChangeScreenParametersNotification` — отмена режима.
- [Carbon-хоткеи — легаси API] → принятый индустрией путь через `global-hotkey`; альтернативы (NSEvent global monitor) не перехватывают события.
- [Ретенция удаляет файлы в пользовательской папке] → чистим только файлы своего паттерна имени; лимит и папка — поля конфига.
- [Захват «заморожен», а меню-бар спрятан оверлеем] → это семантика заморозки, осознанное поведение.
- [Модификаторы нажаты при завершении drag] → завершение по mouse up игнорирует состояние модификаторов.

## Migration Plan

Greenfield: деплой — сборка `cargo build --release` + бандл `.app` (Info.plist с `LSUIElement`) копированием; миграций нет. Конфиг и папка снимков создаются при первом запуске. Откат — удалить `.app`, конфиг и `~/Pictures/minisnap` остаются безвредными.

## Open Questions

- Подсветка рамки окна под курсором в idle (превью клика-по-окну): на макете её нет, в спеках не требуется; добавить можно в любой момент без изменения спек — решить при полировке оверлея.
- Иконка в меню-баре: временная монохромная заглушка до появления фирменной.
- Точный зум лупы (8x/10x) и диаметр — подобрать вручную на Retina.
