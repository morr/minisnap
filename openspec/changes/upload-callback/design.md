# Design

## Context

Сегодня: `UploadBackend::upload(&self, png, name, jobs: Sender<MainJob>)` — бэкенд сам отправляет `MainJob::UploadFinished{result}` из completion-блока NSURLSession (очередь сессии, фоновый поток). `upload_file` прокидывает `jobs`. `app.rs::start_upload` передаёт клон `jobs_tx`. Комбинации «каждая попытка → один исход» обеспечивает цепочка `upload_attempt` (409 → следующий суффикс).

## Goals / Non-Goals

**Goals:**
- Развернуть зависимость: `upload.rs` больше не знает `app::MainJob`; интерфейс говорит «доложи исход один раз».
- Обёртка «исход → MainJob::UploadFinished → тик» живёт в `app.rs` рядом с остальным насосом задач.

**Non-Goals:**
- Не меняем HTTP-механику, ретраи, имена, обратную связь (спека `shot-upload` неизменна).
- Не схлопываем трейт в конкретный бэкенд — он остаётся живой точкой выбора провайдера.
- Не трогаем агентскую семантику (`initiated`/`uploading`) и кнопку редактора.

## Decisions

### `FnOnce(Result<String, String>) + Send` вместо канала

Колбэк вызывается ровно один раз — в конце цепочки попыток (успех, исчерпание имён, сбой), из completion-блока на очереди сессии; отсюда `Send`. Альтернатива — канал `Sender<Result<…>>` — отвергнута на разборе: симметрична существующему механизму, но потребовала бы перекачивающий поток/адаптер в `app.rs`, тогда как колбэк оборачивается в одно `move`-замыкание на `jobs_tx`.

`upload_file` читает файл и зовёт `backend.upload(png, name, on_done)`; локальная ошибка чтения возвращается `Err` как сегодня (колбэк не вызывается), состояние кнопки откатывает вызывающая сторона — семантика без изменений.

### Обёртка в `app.rs`

`start_upload` строит `on_done = move |result| { let _ = jobs_tx.send(MainJob::UploadFinished { result }); }` — `mpsc::Sender` потокобезопасен, тик перекачивает исход на главный поток как сегодня. Точка, где чужой исход становится задачей приложения, — в приложении.

## Risks / Trade-offs

- [Колбэк не вызовётся вовсе (задача потеряна)] → Каждая ветка цепочки попыток завершается вызовом; сегодня те же гарантии даёт `jobs.send` — регресс на живом приложении (успех и сбой загрузки доходят до кнопки и диалога).
- [Паника в колбэке на очереди сессии] → Тело колбэка — один `send`; паникоопасных операций нет.

## Migration Plan

Сначала меняется трейт и `ArtifactsBackend` (цепочка накапливает исход и зовёт колбэк один раз), затем `upload_file`, последней — обёртка в `start_upload`. Юнит-тесты чистых частей (`upload_name`, `parse_reply`, `build_backend`) не затронуты; добавляется тест «колбэк вызывается один раз» на фейковом бэкенде. Откат — revert change.
