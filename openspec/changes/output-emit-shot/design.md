# Design

## Context

Замыкание в `AppController::capture_ready` (`src/app.rs` ~1470–1504): `output::crop → sound::play_shutter → output::copy_to_pasteboard → output::save_to_file(save_dir, retention, scale) → MainJob::OpenEditor → (Upload) weak.load() → handle_upload_request`. Колбэк выполняется на главном потоке из `finish()` оверлея. Спека `capture-output` закрепляет сами эффекты и их пользовательскую видимость, порядок между ними закреплён нынешней реализацией и переносится дословно.

## Goals / Non-Goals

**Goals:**
- Последовательность эффектов — внутренность `output.rs`; контроллер вызывает один вход и получает путь.
- Ошибки шагов конвейера — читаемые `Err`, как сегодня в лог.

**Non-Goals:**
- Не меняем набор и порядок эффектов, политику `CaptureKind` (открытие редактора, запрос загрузки), шов оверлея.
- Не переносим звук в `output.rs` как модуль — остаётся `sound.rs`, конвейер его вызывает.

## Decisions

### Граница: эффекты внутри, политика снаружи

`emit_shot(image, pixel_rect, scale, dir, retention) -> Result<PathBuf, String>` в `output.rs` владеет последовательностью `crop → shutter → pasteboard → save` и возвращает сохранённый путь. Открытие редактора (`MainJob::OpenEditor` с `only_if_visible`) и запрос загрузки (`CaptureKind::Upload` → `handle_upload_request`) — политика приложения, остаются в замыкании. Альтернатива — протащить `CaptureKind` и колбэки внутрь — отвергнута на разборе: модуль тянул бы политику оболочки.

Пустое выделение (`crop → None`) сегодня — ранний выход с логом; `emit_shot` возвращает `Err` с той же формулировкой, замыкание логирует.

### Дом — `output.rs`, без нового файла

Конвейер эффектов и есть предмет домена вывода; отдельный файл дробил бы домен.

### Сигнатура передаёт папку и ретенцию явно

`save_dir`/`retention` замыкание берёт из config сегодня — так и остаётся: параметры входа, а не глобальное состояние.

## Risks / Trade-offs

- [Порядок «звук до буфера» или «буфер до звука» незаметно меняется] → Перенос дословный, одним блоком; регресс на живом приложении (звук слышен в момент завершения, снимок в буфере).
- [Ошибка раннего шага глотает поздние незаметно] → Семантика как сегодня: неуспешный `crop` — ранний `Err`; сбой буфера логируется, сохранение продолжается (нынешнее поведение переносится: буфер — не блокирующий шаг).

## Migration Plan

Функция добавляется и покрывается юнит-тестом на синтетическом кадре (порядок шагов наблюдаем по побочным эффектам в фейках — путь файла, буфер мокнуть нельзя, проверить сохранённый PNG и лог); затем замыкание переводится на неё. Откат — revert change.
