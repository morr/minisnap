# Proposal

## Why

Последовательность «что происходит со снимком после выделения» — обрезка кадра, звук затвора, буфер обмена, тихое сохранение — закодирована ровно один раз, но внутри замыкания колбэка оверлея в `app.rs` (`capture_ready`, ~1470–1504), вперемешку с weak-ссылкой на контроллер и политикой вида захвата. Новый шаг вывода означал бы правку контроллера, хотя весь конвейер — это и есть предмет домена `output.rs`.

## What Changes

- В `output.rs` появляется функция `emit_shot` (имя может уточниться): принимает кадр, пиксельный прямоугольник выделения и масштаб дисплея, выполняет последовательность эффектов — `crop → play_shutter → copy_to_pasteboard → save_to_file` — и возвращает сохранённый путь (`Err` — читаемая причина сбоя шага). Порядок эффектов сохраняется нынешний, поведение по спеке `capture-output` неизменно.
- Замыкание в `capture_ready` сокращается: `Selected → emit_shot → follow-up` (отправка `MainJob::OpenEditor` с флагом видимости и, для `CaptureKind::Upload`, запрос загрузки). Политика приложения остаётся в `app.rs`, конвейер эффектов уходит в домен вывода.
- Шов оверлея (`OverlayOutcome` / `on_done`) не меняется.

Чистая перестановка: все эффекты, их порядок и сообщения об ошибках наблюдаемо те же — спеки не затрагиваются.
