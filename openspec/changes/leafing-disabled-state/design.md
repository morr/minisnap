# Design

## Context

Состояние тулбара живёт одним пушем: окно собирает `ToolbarState` чистой редукцией `editor_toolbar::toolbar_state(doc, …)` из документа и ivars и пушит из `redraw()`; `ToolbarView::set_state` — единственный вход полосы. Кнопки листания ◄/► — `NSButton` с шевронами `chevron.left`/`chevron.right`, лежат в общей ivars `tool_buttons`, тинг `ICON_TINT`, hover-плита — общий проход `hover_at` (плиты — `plates.rs`), клик — action `pageClicked:` → `ToolbarEvent::PagePrevious/PageNext`. `update_tool_highlight` при каждом пуше перекрашивает тинг всех кнопок vec — листающих тоже.

Само листание — `page(delta)` в окне: `output::sorted_shots(&save_dir)` (чтение каталога + сортировка по времени), позиция открытого снимка, кламп к краям, no-op при совпадении цели. Ни одно поле `ToolbarState` про позицию снимка в списке не говорит, и у тулбара нет прецедента disabled-контроля (`can_undo`/`can_redo` в снимке есть, UI под них нет).

## Goals / Non-Goals

**Goals:**
- Disabled state кнопок листания синхронен показанному снимку: обновляется каждым пушем, тем же механизмом, что метка файла и подсветка инструмента.
- Доступность листания считается в чистой редукции и покрыта юнит-тестами.
- Цвет disabled — `#999999`; hover-подсветка и клик на disabled-кнопке не работают.

**Non-Goals:**
- Клавиатурное листание ←/→ не меняется (края по-прежнему просто останавливают его).
- Тултипы «Previous shot»/«Next shot» не трогаются.
- Отдельный выключатель на клавиатурное листание не вводится — требование только про кнопки.

## Decisions

**D1 — Доступность листания в `ToolbarState`.** Снимок получает `can_page_prev: bool` и `can_page_next: bool`; редукция `toolbar_state` принимает их параметрами и кладёт в снимок, ничего не считая сама. Альтернативы: считать в тулбаре из имени файла — отклонено, тулбар не знает ни папку, ни листинг (интерфейс полосы — `set_state`/события); хранить позицию снимка в документе — отклонено, позиция в списке файлов — не свойство документа.

**D2 — Источник правды — листинг папки на каждый пуш.** В оконном `toolbar_state()`: `output::sorted_shots(&ivars.save_dir.borrow())`, позиция открытого снимка в листинге; `can_page_prev = index > 0`, `can_page_next = index + 1 < len`; снимка нет или он не найден в листинге — оба `false`. Каталог уже читается на каждый клик листания (`page`), а пуши идут темпом пользовательских действий (выделение, undo/redo, рефит, листание), не в кадре; чтение каталога сотен файлов несопоставимо с ценой полного redraw канвы. Альтернатива — кеш в ivars с инвалидацией: отклонено, даёт второй источник истины и список правил инвалидации ради микросекунд readdir.

**D3 — Disabled без `setEnabled`: собственная краска и собственный guard.** Цвет disabled — явное требование, поэтому системный disabled-рендер не используется: `setEnabled` на кнопках листания не трогается, тинг шеврона ставим сами — `PAGE_DISABLED_TINT = #999999` рядом с `ICON_TINT`. Клик глушится guard'ом в `__page_clicked` по ivar, hover-скип в `hover_at` — по тому же ivar; AppKit не шлёт событий, мы ни от чьей отрисовки не зависим (на новых macOS системная отрисовка disabled template-образа ненадёжна, см. грабли с подслоями и hit-test в скилле). Нажатие тоже рисует система — ячейка кнопки в pressed-состоянии перекрашивает шеврон в системный вид, и disabled-кнопка под курсором «оживает»: `update_page_buttons` гасит это флагом подсветки ячейки — `setHighlightsBy(NoCellMask)` на disabled-кнопке, обычная маска (`ContentsCellMask | PushInCellMask`) на enabled, так что enabled-кнопка сохраняет прежний нажатый отклик. Trade-off: accessibility не видит кнопки disabled — сознательно, ради зафиксированного цвета.

**D4 — Листающая пара красится собственным проходом.** `set_state` зовёт новый проход `update_page_buttons(can_page_prev, can_page_next)`: тинг шевронов по доступности, ivars для hover/клика. Существующие проходы при этом не должны перезатирать результат: в `update_tool_highlight` листающие теги пропускаются при покраске тинга (плитка им и сейчас не назначается), в `hover_at` плитка листающих ставится как раньше, но disabled-кнопка скипается — как активный инструмент. Проход сам снимает hover-плиту с disabled-кнопки: курсор мог остаться на кнопке с момента, когда она была enabled, и hover_at без движения мыши не придёт — плита гаснет пушем (в `animate_plate_changes`, как у остальных проходов плит). Порядок внутри `set_state` не важен, проходы больше не пересекаются по кнопкам.

## Risks / Trade-offs

- [Порядок проходов краски] → `update_tool_highlight` больше не красит тинг листающих, иначе пуш вернул бы `ICON_TINT` после `update_page_buttons`; живой прогон 5.1 проверяет, что disabled-шеврон остаётся `#999999` после листания.
- [Скан каталога на каждый пуш] → readdir на сотни файлов — микросекунды; то же чтение уже происходит на каждый клик листания. Если когда-нибудь станет заметно — кеш по D2, изоляция одна точка (`toolbar_state()` окна).
- [Guard в `__page_clicked` не защищает клавиатурный вызов] → клавиатура листает через свой путь окна, не через кнопку; требование про disabled касается кнопок, клавиатурное поведение не меняется.
- [Юнит-тесты редукции] → сигнатура `toolbar_state` пополняется двумя параметрами; существующие тесты обновляются механически, новые — про проброс полей в снимок.

## Migration Plan

Не требуется: UI-изменение, данных и форматов не касается. Откат — реверс коммитов.
