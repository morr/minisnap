# Spec Delta

## Purpose

Обращение с разрешением Screen Recording: приложение само обнаруживает его отсутствие при запуске, объясняет проблему пользователю понятной ошибкой в консоли и диалогом с инструкцией по исправлению, не даёт захвату работать без права и подхватывает выданное право с минимальными действиями пользователя.

## ADDED Requirements

### Requirement: Проверка права при запуске

При запуске приложение SHALL проверять наличие права Screen Recording без вызова системного запроса (preflight). Если право не выдано, приложение MUST вывести в stderr понятную однострочную ошибку с указанием, что включить, и показать объясняющий диалог; процесс при этом продолжает работать (иконка в меню-баре и меню доступны). Если право выдано, приложение SHALL запускаться штатно без диалогов.

#### Scenario: Запуск без права

- **WHEN** приложение запущено и право Screen Recording не выдано
- **THEN** в stderr выведена понятная ошибка с указанием, где включить право, и показан объясняющий диалог; процесс продолжает работать

#### Scenario: Запуск с правом

- **WHEN** приложение запущено и право Screen Recording выдано
- **THEN** приложение работает штатно, диалоги и ошибки не показываются

### Requirement: Диалог объясняет проблему и путь исправления

Объясняющий диалог MUST сообщать: что именно не работает без права, какой раздел Системных настроек открыть (Конфиденциальность и безопасность → Запись экрана), какому приложению какой доступ дать и что сделать после выдачи. Инструкция MUST учитывать способ запуска: при запуске из собранного `.app`-бандла право включается для minisnap, при запуске без бандла — для приложения-хоста (терминал или IDE), поскольку в списке TCC фигурирует именно оно.

#### Scenario: Приложение запущено из бандла

- **WHEN** диалог показан, а приложение запущено из `.app`-бандла
- **THEN** инструкция называет minisnap как приложение, которому нужно включить «Запись экрана»

#### Scenario: Приложение запущено без бандла

- **WHEN** диалог показан, а приложение запущено без бандла (например, из терминала или IDE)
- **THEN** инструкция называет приложение-хост (терминал или IDE), которому нужно включить «Запись экрана»

### Requirement: Кнопка открытия настроек

Диалог SHALL иметь кнопку, открывающую Системные настройки прямо на панели Конфиденциальность и безопасность → Запись экрана.

#### Scenario: Клик по кнопке настроек

- **WHEN** пользователь нажимает кнопку открытия настроек в диалоге
- **THEN** Системные настройки открываются на панели «Запись экрана»

### Requirement: Захват без права не запускается

Если право Screen Recording не выдано, попытка захвата — глобальным хоткеем или пунктом меню Capture Frozen Area — MUST NOT запускать режим выделения; вместо этого приложение показывает объясняющий диалог.

#### Scenario: Хоткей без права

- **WHEN** право не выдано и пользователь нажимает глобальный хоткей захвата
- **THEN** режим выделения не запускается, показывается объясняющий диалог

#### Scenario: Пункт меню без права

- **WHEN** право не выдано и пользователь выбирает пункт меню Capture Frozen Area
- **THEN** режим выделения не запускается, показывается объясняющий диалог

### Requirement: Отслеживание выдачи права

Пока объясняющий диалог открыт, приложение SHALL опрашивать наличие права и обнаруживать выдачу без действий пользователя. Когда право выдано, диалог MUST обновиться и предложить перезапустить приложение, поскольку разрешение применяется к уже запущенному процессу только после перезапуска. После перезапуска приложение SHALL работать штатно без повторных подсказок.

#### Scenario: Право выдано при открытом диалоге

- **WHEN** пользователь включает право в Системных настройках, пока диалог открыт
- **THEN** приложение обнаруживает выдачу, и диалог обновляется с предложением перезапустить приложение

#### Scenario: Перезапуск после выдачи

- **WHEN** пользователь подтверждает перезапуск в диалоге
- **THEN** процесс завершается и запускается заново, после чего захват работает и диалоги о праве не показываются
