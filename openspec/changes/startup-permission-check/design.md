# Design

## Context

Смотри proposal.md (Why). Точка старта — `AppController` в `src/app.rs`: `applicationDidFinishLaunching` сейчас только логирует, захват стартует из `start_capture` (хоткей-диспетчер в `tick:` и action меню `captureFrozenArea:`), ошибки ScreenCaptureKit печатаются в `capture_ready`. В `src/permission.rs` уже есть непромптящий `preflight_screen_capture()` (помечен dead_code «wired into the startup check in section 7») — его и подключаем. `NSAlert` уже включён в фичи `objc2-app-kit`. Активный change `mvp-frozen-area-capture` содержит нереализованный раздел 7 с задачами 7.1–7.2 и дельту той же capability — этот change забирает её себе (см. Migration Plan), чтобы при архивации дельты не задвоились.

## Goals / Non-Goals

**Goals:**

- Проверка права при запуске без побочных системных промптов; понятная ошибка в stderr и объясняющий диалог с инструкцией.
- Одна точка блокировки захвата, работающая и для хоткея, и для меню.
- Обнаружение выдачи права, пока диалог открыт, и перезапуск одной кнопкой.

**Non-Goals:**

- Accessibility — приложению не нужен (см. докамодуль `src/permission.rs`).
- Локализация диалога; авто-перезапуск без подтверждения; отслеживание *отзыва* права у работающего процесса; реакция на ошибку -3801 в рантайме поверх gating'а (при gating'е она фактически недостижима).

## Decisions

1. **Preflight, не системный промпт.** При старте вызывается только `CGPreflightScreenCaptureAccess()`; `CGRequestScreenCaptureAccess()` (штатный TCC-промпт) не используем: системное окно не объясняет, что именно включить и кому давать доступ, а наш диалог — объясняет.

2. **Диалог — `NSAlert` + `runModal`.** Две кнопки: «Открыть Системные настройки» и «Позже». Перед показом — `NSApplication.activate(ignoringOtherApps: true)`, иначе accessory-приложение без Dock-иконки рискует показаться позади активного окна. Альтернатива — собственное окно со стеком — избыточна для двух абзацев текста. Тик-таймер уже висит в `NSRunLoopCommonModes`, куда входит и модальная панель, — диспетчеризация хоткеев не останавливается, а накопленные события после закрытия диалога отработают через gating.

3. **Способ запуска — по `NSBundle.main.bundleIdentifier`.** У бандла он равен `app.minisnap.minisnap`, у «голого» бинарника — nil; возможно, потребуется включить фичу `NSBundle` у `objc2-foundation`. Имя хост-приложения (какой именно терминал) не определяем: для этого пришлось бы читать родительский процесс через sysctl ради одной строки текста — в диалоге пишем «приложение, из которого запущен minisnap (терминал, IDE и т.п.)».

4. **Gating — в `start_capture`, preflight на каждую попытку.** Вызов дешёвый, и проверка в одной точке покрывает сразу хоткей, пункт меню и случай «право выдали после старта». Проверяются только захваты: `OpenLatest` право не требует. Ошибку -3801 в `capture_ready` не трогаем — она остаётся страховкой.

5. **Опрос выдачи — отдельный `NSTimer` на 2 c**, живёт только пока диалог открыт (инвалидируется при выдаче или закрытии), а не глобальный tick на 50 мс: TCC не шлёт уведомлений, но дёргать префлайт 20 раз в секунду незачем. При обнаружении выдачи: лог в stderr и перевод диалога в состояние «право выдано — перезапустить?» с кнопками «Перезапустить» и «Позже».

6. **Перезапуск — `Command::new(current_exe).spawn()` + `NSApplication.terminate`.** Для бандла `current_exe` указывает внутрь `minisnap.app` — TCC привязан к bundle id, перезапущенный процесс наследует выданное право. Путь через `NSWorkspace` (замена процесса) отклонён как избыточный. Проверка точного URL панели (`x-apple.systempreferences:com.apple.preference.security?Privacy_ScreenCapture`) на macOS 15 — при реализации; фолбэк — открытие Системных настроек на главной.

7. **Языки текстов.** Консоль — английский, в стиле существующих логов (например, `error: Screen Recording permission is not granted; open System Settings > Privacy & Security > Screen Recording and enable minisnap, then restart`). Диалог — русский: это личная утилита, l10n-инфраструктуры нет и она вне скоупа; интерфейс меню остаётся как есть.

## Risks / Trade-offs

- [runModal в `did_finish_launching` останавливает обычный run loop] → тик живёт в common modes и продолжит копить хоткей-события; без права захват всё равно gated, «Позже» закрывает диалог, приложение остаётся работать.
- [TCC-статус кешируется процессом: префлайт может соврать после выдачи без перезапуска] → поэтому после выдачи предлагаем именно перезапуск, а gating делает префлайт перед каждой попыткой (в новом процессе статус верный).
- [Перезапуск «голого» бинарника теряет контекст терминала (cwd/переменные)] → dev-кейс, допустимо; бандл-запуск — основной сценарий.
- [Кнопка настроек ведёт не туда на будущих версиях macOS] → фолбэк на главную страницу Системных настроек; проверяется при реализации (задача в tasks.md).

## Migration Plan

1. Первая задача реализации — вычистить `mvp-frozen-area-capture`: удалить его `specs/screen-recording-permission/spec.md` и задачи 7.1–7.2 (с пометкой «передано в startup-permission-check»). После этого порядок архивации двух изменений безразличен.
2. Дальше — обычная реализация по tasks.md этого change и `openspec archive`. Откат — git revert соответствующих коммитов.
