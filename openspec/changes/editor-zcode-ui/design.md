# Design

## Context

См. `proposal.md` (Why). Текущее состояние: `src/editor_window.rs` строит окно с верхней полосой на `NSVisualEffectView` (`HUDWindow`, принудительно тёмный appearance), горизонтальным `NSStackView` (листание + имя файла | свотч + слайдер | инструменты), канвой на всю ширину с шахматкой и центрированным кадром (`frame_rect`). Traffic-lights системные, видим только close. `refit_window` резервирует `TOOLBAR_HEIGHT` сверху и не даёт окну стать уже `min_width` тулбара. Всё меняется внутри одного файла и одного класса; механизмы ввода, хит-теста, команд и сессий не трогаем.

## Goals / Non-Goals

Goals:

- Раскладка «левая колонка + вложенная карточка» как у zcode, светлый плоский вид с точными цветами из референса.
- Живые системные кнопки: close — закрыть, зелёная — полный экран, жёлтая — спрятать окно.
- Сохранить все существующие механики: hover, drag окна, кроп/ресайз, поповер палитры, ввод текста, листание.

Non-Goals:

- Тёмная тема / следование системной теме: цвета фиксированные светлые (как и сейчас тема фиксированная тёмная).
- Кнопки undo/redo, показ имени файла, изменение набора инструментов и их поведения.
- Новые зависимости; изменения в `src/editor/*` (документ, рендер элементов, сессии).

## Decisions

### 1. Карточку рисует канва, отдельного NSView нет

`EditorView::draw` рисует: фон всего окна `#F2F2F2` → путь скруглённого прямоугольника карточки (заливка `#F8F8F8`, бордер 1 pt `#E0E0E0`, радиус ~8 pt) → клип по этому пути → шахматка и композит кадра в `frame_rect`. Новый метод `card_rect()`: bounds минус `TOOLBAR_WIDTH` слева, минус 4 pt сверху/справа/снизу (контакт с тулбаром вплотную — по описанию; при желании сделать равный бордюр меняется одна константа `CARD_GAP_LEFT = 0`). `frame_rect` центрируется в `card_rect`, не в bounds.

Альтернатива — карточка отдельным layer-backed `NSView` — отклонена: лишняя сущность, а шахматку и клип всё равно считает канва; сейчас вся служебная графика уже живёт в `draw`.

### 2. ToolbarPanel — прозрачная колонка без вибрации

Базовый класс `ToolbarPanel` меняется с `NSVisualEffectView` на `NSView` (wantsLayer, без заливки): фон колонки — это фон канвы `#F2F2F2`, панель только принимает tracking area и `mouseDown` → `performWindowDragWithEvent`. Материал, тёмный appearance окна (`NSAppearanceNameDarkAqua`) и `BAR_HAIRLINE`/`BAR_DIVIDER`-константы под тёмную тему уходят; окну ставится светлый appearance, чтобы системные контролы (поповер, кнопки) рендерились светлыми.

### 3. Колонка: верхняя строка + вертикальный стек

- Верхняя строка (высота ~40 pt): ведущий отступ `TRAFFIC_ROW_PAD` (~70 pt — кластер системных кнопок при трёх видимых кружках кончается ~64 pt от края) + кнопки ◄/► `28×28`.
- `TOOLBAR_WIDTH` = естественная ширина верхней строки (≈ 70 + 28 + 8 + 28 + 12 ≈ 146 pt) — одна константа, колонка не сужается меньше.
- Ниже — вертикальный `NSStackView` (orientation `Vertical`, выравнивание по центру X): свотч цвета → вертикальный слайдер толщины → горизонтальный разделитель (18×1) → девять кнопок инструментов группами (после Pen и Blur — `BAR_ZONE_SPACING`).
- Минимальная высота окна = высота строки + fitting-высота стека (порядка 470 pt): `min_width` в ivars заменяется на `min_height`; ширина окна всегда = `TOOLBAR_WIDTH + CARD_GAP + frame_w`, минимальная ширина перестаёт быть ограничением (колонка вертикальная, ей нужна высота).

Инвариант стека (из скилла): размеры видов — только autolayout; у вертикального слайдера `intrinsicContentSize` меняется на 28×90, свотч и кнопки остаются на констрейнтах 28×28.

### 4. Слайдер толщины вертикальный

`WidthSliderView` переписывается на вертикальную ориентацию: трек по вертикали, низ = `STROKE_MIN`, верх = `STROKE_MAX`, ручка ездит по Y; контракт (`doubleValue` / `setDoubleValue:` / `widthChanged:` / `sync_width_slider`) не меняется. Поворот горизонтального слайдера трансформом отклонён — ломает хит-тест и accessibility.

### 5. Светлая палитра констант

| Что | Было (тёмная тема) | Станет |
|---|---|---|
| Фон окна/тулбара | вибрация HUDWindow | `#F2F2F2` |
| Карточка | — | `#F8F8F8` + бордер `#E0E0E0`, радиус 8 |
| Иконки | белый `#FFFFFFCC` | `#262626` |
| Hover плитки | белый wash 8 % | чёрный wash ~6 % (`rgba(0,0,0,0.06)`), радиус ~7 — метрики плитки 28×28 / иконки ~16 pt с референса |
| Активный инструмент | системный акцент | без изменений (акцентная плашка) |
| Свотч-обводка | белый | `rgba(0,0,0,0.15)`, hover 0.3 |

Хром рамки кропа/ресайза (метка «W × H», кнопка OK) перекрашивается под светлый фон (тёмный текст вместо белого); затемнение вне рамки не меняется. Поповер палитры наследует светлый appearance окна.

### 6. Живые системные кнопки

Убирается цикл `setHidden(true)` для Miniaturize/Zoom. Поведение: зелёной кнопке ставится target = окно, action = `toggleFullScreen:`; жёлтой — target = окно, action = `orderOut:` (прячет окно без миниатюризации в док: приложение accessory, стандартная миниатюризация сделала бы окно недостижимым). `setReleasedWhenClosed(false)` и переиспользование окна сохраняются: спрятанное окно возвращается любым `show_shot` (захват с редактированием, «открыть последний», листание). Полноэкранный режим системный: кадр центрируется в карточке заново при resize, traffic-lights автоскрываются до наведения — нормальное поведение macOS.

### 7. refit_window под новую геометрию

Доступная область: `visibleFrame` главного экрана минус `TOOLBAR_WIDTH` + 4 (горизонтальный хром) по ширине и минус 8 (два отступа карточки) по высоте. Итог: `width = TOOLBAR_WIDTH + CARD_GAP + frame_w`, `height = max(frame_h + 8, min_height)`. `fit_size` (вписывание вниз без увеличения) и якорение левого верхнего угла при повторных подгонках — без изменений; первое открытие по-прежнему центрирует.

## Risks / Trade-offs

- [Ширина кластера traffic-lights плавает между версиями macOS] → `TRAFFIC_ROW_PAD` и `TOOLBAR_WIDTH` — константы с комментарием; сверка по факту на macOS 15, при расхождении правится одна строка.
- [Колонка ~146 pt съедает ширину у мелких снимков] → принято: окно просто шире кадра, шахматка заполняет карточку (спека это покрывает сценарием «Мелкий кадр и минимум окна»).
- [Жёлтая кнопка выглядит как «свернуть», а прячет окно] → поведение согласовано в спеке; возврат — любой захват с редактированием или «открыть последний».
- [Вертикальный слайдер — новый код рисования и хит-теста] → контракт слайдера не меняется, синхронизация с выделенным элементом (`sync_width_slider`) тестируется руками по сценарию спеки.
- [Вертикальный стек может схлопнуть виды без autolayout-размера] → известный инвариант: констрейнты/`intrinsicContentSize` у всех arranged subviews проверяются в задаче сборки колонки.
- [OpenSpec запрещает выпадение сценариев из MODIFIED-требования] → имена сценариев стабильны («Миниатюризация и зум скрыты», «Имя файла в тулбаре», «Перетаскивание за полосу»), содержание переписано под новое поведение; имена — исторические, при следующем пересмотре спеки их можно обновить отдельным change'ом.

## Migration Plan

Один коммит в `src/editor_window.rs` (+ дельта спеки и скилл `minisnap-editor`). Откат — revert коммита; форматы сессий и файлов не меняются, миграции данных нет.

## Open Questions

Точная прозрачность/радиус hover-плитки и радиус карточки сверяются с референсом визуально в ходе apply (в пределах констант из решения 5) — на спеку и разбиение задач не влияет.
