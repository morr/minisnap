# Design

## Context

См. `proposal.md` (Why). Текущее состояние рабочей ветки: светлая палитра и прозрачный `ToolbarPanel` уже переведены (первый коммит change'а делал левую колонку — она переделывается на полосу), канва на всю высоту окна красит фон `#F2F2F2`. Мастер-состояние: `src/editor_window.rs` — верхняя полоса на `NSVisualEffectView` (`HUDWindow`, тёмный appearance), горизонтальный `NSStackView` (листание + имя файла | свотч + слайдер | инструменты), канва ниже полосы с шахматкой и центрированным кадром. `refit_window` резервирует высоту полосы сверху и не даёт окну стать уже `min_width` тулбара. Механизмы ввода, хит-теста, команд и сессий не трогаем.

## Goals / Non-Goals

Goals:

- Раскладка «светлая полоса + вложенная карточка» как у zcode, с точными цветами референса.
- Сохранить все существующие механики: hover, drag окна, кроп/ресайз, поповер палитры, ввод текста, листание.
- Системные закругление углов и тень окна — нетронутыми.

Non-Goals:

- Тёмная тема / следование системной теме: цвета фиксированные светлые.
- Кнопки undo/redo, показ имени файла, изменение набора инструментов и их поведения.
- Живые системные кнопки — change `editor-system-buttons`.
- Новые зависимости; изменения в `src/editor/*` (документ, рендер элементов, сессии).

## Decisions

### 1. Карточку рисует канва, отдельного NSView нет

Канва снова живёт под полосой (как в мастере). `EditorView::draw` рисует: скруглённый путь карточки (заливка `#F8F8F8`, бордер 1 pt `#E0E0E0`, радиус ~8 pt) → клип по пути → шахматка и композит кадра. Фон окна канва NOT красит: цвет хрома (`#F2F2F2`) задаёт `NSWindow.backgroundColor`, поэтому системное закругление углов и тень остаются нетронутыми (урок change'а: бит `FullScreen` и заливка всей канвы ломают вид углов). Новый метод `card_rect()`: bounds канвы минус `CARD_GAP` (4 pt) со всех четырёх сторон. `frame_rect` центрируется в `card_rect`.

Альтернатива — карточка отдельным layer-backed `NSView` — отклонена: лишняя сущность, а шахматку и клип всё равно считает канва.

### 2. ToolbarPanel — прозрачная полоса без вибрации

`ToolbarPanel` — `NSView` (без заливки; уже сделано первым коммитом): фон полосы — это `window.backgroundColor` `#F2F2F2`, панель принимает tracking area и `mouseDown` → `performWindowDragWithEvent`. Материал, тёмный appearance и hairline-константы под тёмную тему уходят; окну ставится светлый appearance (`Aqua`), чтобы системные контролы (поповер, кнопки) рендерились светлыми. Маска стиля окна не расширяется никакими битами, влияющими на хром.

### 3. Полоса: один горизонтальный ряд

Высота полосы `TOOLBAR_HEIGHT` = 40 pt. Состав слева направо: ведущий отступ `BAR_LEADING_PAD` (70 pt — кластер трёх traffic-lights кончается ~64 pt от края; место готово под `editor-system-buttons`), кнопки листания ◄/► 28×28 с плотным интервалом 4 pt внутри пары (как в zcode), вертикальный разделитель 1×18, свотч цвета 28×28 и горизонтальный слайдер толщины (90×24), разделитель, девять инструментов тремя группами (после Pen и Blur — `BAR_ZONE_SPACING`). Базовый интервал — 8 pt. Кнопки листания и инструменты несут hover-плитку: слой 28×28, радиус ~7, заливка ~6 % чёрного на hover, акцентная плашка у активного инструмента.

`min_width` = `BAR_LEADING_PAD` + fitting-ширина ряда + правый паддинг (12 pt) — окно не сжимается ниже полосы (метки имени нет, ряд фиксированный).

Инвариант стека (из скилла): размеры видов — только autolayout; у слайдера `intrinsicContentSize` 90×24, свотч и кнопки — констрейнты/инстринсик 28×28.

### 4. Светлая палитра констант

| Что | Было (тёмная тема) | Станет |
|---|---|---|
| Фон окна/полосы | вибрация HUDWindow | `#F2F2F2` через `NSWindow.backgroundColor` |
| Карточка | — | `#F8F8F8` + бордер `#E0E0E0`, радиус 8 |
| Иконки | белый `#FFFFFFCC` | `#262626` |
| Hover плитки | белый wash 8 % | чёрный wash ~6 %, радиус ~7 |
| Активный инструмент | системный акцент | без изменений (акцентная плашка) |
| Свотч-обводка | белый | `rgba(0,0,0,0.15)`, hover 0.3 |
| Разделители | белый 15 % | `separatorColor` |

Хром рамки кропа/ресайза (метка «W × H», кнопка OK) читается на светлом: метка белая поверх затемнения (оно не меняется), OK — акцентная плашка с системным тёмным appearance, чтобы заголовок оставался белым. Поповер палитры наследует светлый appearance окна.

### 5. refit_window под новую геометрию

Доступная область: `visibleFrame` главного экрана минус 8 pt (отступы карточки) по ширине и минус `TOOLBAR_HEIGHT` + 8 pt по высоте. Итог: `width = max(frame_w + 2·CARD_GAP, min_width)`, `height = TOOLBAR_HEIGHT + frame_h + 2·CARD_GAP`. `fit_size` (вписывание вниз без увеличения) и якорение левого верхнего угла при повторных подгонках — без изменений; первое открытие по-прежнему центрирует.

## Risks / Trade-offs

- [Ширина кластера traffic-lights плавает между версиями macOS] → `BAR_LEADING_PAD` — константа с комментарием; в этом change кнопки ещё скрыты, отступ просто резервирует место; сверка по факту при приземлении `editor-system-buttons`.
- [Карточка съедает по 4 pt с каждой стороны] → принято: шахматка в карточке покрывает прозрачный фон, потери площади незаметны.
- [Слайдер остаётся горизонтальным] → вертикальная версия отменена вместе с колонкой; контракт слайдера не менялся.
- [OpenSpec запрещает выпадение сценариев из MODIFIED-требования] → имена сценариев стабильны («Миниатюризация и зум скрыты», «Имя файла в тулбаре», «Перетаскивание за полосу»), содержание переписано под новое поведение; сценарии зелёной/жёлтой кнопок переехали в дельту `editor-system-buttons`.
- [Два change'а правят одно требование параллельно] → дельты независимы; при архивации одного из них второй пересобирает текст.

## Migration Plan

Серия коммитов в `src/editor_window.rs` (+ дельта спеки и скилл `minisnap-editor`). Откат — revert цепочки; форматы сессий и файлов не меняются, миграции данных нет.

## Open Questions

Точная прозрачность hover-плитки и радиус карточки сверяются с референсом визуально в ходе apply (в пределах констант из решения 4) — на спеку и разбиение задач не влияет.
