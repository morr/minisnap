# Design

## Context

Шесть точек `src/editor_window.rs` собирают хвост синхронизации вручную: `handle_mouse_up` (~805), `delete_selected` (~830), `undo_redo` (~868), `agent_command` (~1035), `commit_text_editor` (~1576), `commit_frame_edit` (~1734). Различия между ними фактические, а не политические: коммит открытого текста до команды делают 4 из 6; гашение одноразового инструмента обе существующие ветки выводят из `matches!(cmd, AddElement)`; проверка живости выделения скопирована дословно в `undo_redo` и `agent_command`; refit-или-redraw по смене размера базы — три места. Доступность листания `toolbar_state()` вида считает через `output::sorted_shots` при каждом `redraw()` и пишет обратно в `stroke_width` (~964).

Ядро редактора (`editor/mod.rs`, `editor/drag.rs`) чистое и протестировано; перестановка не выходит за пределы `editor_window.rs` и одного нового модуля.

## Goals / Non-Goals

**Goals:**
- Один владелец протокола «применить и синхронизировать»; точки входа — тонкие обёртки.
- План синхронизации — чистая функция с юнит-тестами без окна.
- Ввод-вывод папки уходит из пути перерисовки; чтение состояния перестаёт мутировать.

**Non-Goals:**
- Не меняем внешние интерфейсы: сигнатуры агентских операций, тулбар, горячие клавиши, поведение undo/redo.
- Не трогаем машину драга, документ, сессии — они уже глубокие.
- Не меняем шов тулбара (`set_state`/`ToolbarEvent`) и чистую редукцию `toolbar_state()` в `editor_toolbar.rs`.

## Decisions

### План синхронизации — чистая функция, а не метод вида

`src/editor/sync.rs`: функция принимает производные факты (`made_element: bool`, размер базы до/после, `selection_alive: bool`) и возвращает плоскую структуру `SyncPlan { drop_tool: bool, selection: Keep | Clear, refit: bool }`. Альтернативы, отвергнутые на разборе: список действий (порядок исполнения становился бы частью интерфейса) и метод на `EditorView` (протокол остался бы нетестируемым без окна).

Вход принимает факты, а не `Command`/enum источника: плану не нужно знать про команду — «создан элемент» выводит вызывающая сторона (`matches!(cmd, AddElement)`), и undo/redo честно передают `false`, сохраняя нынешнее поведение (undo инструмент не гасит).

### Один вход, полный протокол всегда

Метод вида применяет команду так: (1) безусловный коммит открытого текстового поля — no-op без поля; команда, рождённая этим коммитом, проходит через тот же вход (рекурсия ограничена одним уровнем — поле закрывается); (2) `before → shot.apply(cmd) → after`; (3) `sync_plan(факты)`; (4) исполнение плана в фиксированном порядке: выделение → инструмент → refit-или-redraw → пуш тулбара. Различия «делать ли шаг» не передаются флагами — они выводятся из фактов.

Существующие шесть точек остаются обёртками (внешние сигнатуры — возврат `Ok(bool)` у undo и т.п. — не меняются); прямых вызовов входа снаружи не появляется.

### Исполнитель плана принимает правило ширины штриха

Правило «ширина выделенного элемента со штрихом становится шириной для новых» переезжает из read-пути `toolbar_state()` в исполнитель плана: оно срабатывает при смене выделения (включая его сброс), а не при каждом чтении. Агентский `GET /state` возвращает те же значения — мутация была идемпотентной, — но перестаёт существовать.

### Список снимков — модуль с событийным кешем

`ShotList` (новый модуль рядом с `editor/`, например `src/editor/shot_list.rs`): владеет `save_dir`, кеширует отсортированный листинг и позицию текущего снимка; интерфейс — `set_current(path)`, `neighbors() -> (bool, bool)`, `page(delta) -> Option<PathBuf>`. Листинг внедряется (для `page` и тестов — снимок `Vec<PathBuf>`), поэтому модуль тестируется без диска. Вид теряет ivar `save_dir`; `EditorWindow::new` строит список из пути.

Кеш инвалидируется событиями: показ снимка (`display_shot`), сохранение нового файла (звено в `app.rs` после сохранения оповещает окно — уже существующий `MainJob::OpenEditor` путь), листание. Альтернатива — проба mtime каталога на каждый кадр — отвергнута на разборе: диск оставался бы в пути отрисовки; ценой является отложенное отражение внешних изменений, что зафиксировано дельтой спеки.

## Risks / Trade-offs

- [Рекурсия «коммит текста → команда → вход» зацикливается] → Поле закрывается до применения рождённой команды, второй вход открытого поля не видит; тест на сценарий «Enter при открытом поле во время драга».
- [Кеш листания расходится с папкой после внешних удалений] → Спека закрепляет момент отражения; `page()` при неудаче открытия соседа пересчитывает список.
- [Поведенческий дрейф при сведении шести веток в одну] → Прежние различия протокола переносим дословно; сравнение поведения через агентский канал на живом приложении (undo/redo после удаления, refit после кропа, гашение инструмента после текста) — тем же набором шагов, что регресс при прошлых правках.
- [Событие «сохранение нового снимка» проходит мимо окна, если редактор скрыт] → `OpenEditor { only_if_visible }` уже несёт путь — на его обработке окно и обновляет список; скрытое окно получит свежий список при следующем показе.

## Migration Plan

Чистая перестановка внутри одного change: `sync.rs` + `shot_list.rs` с тестами приходят первыми, затем шесть точек переводятся на вход по одной (каждый шаг — зелёные тесты), последними уходят `save_dir` ivar и write-back. Откат — revert change.
