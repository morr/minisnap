# Proposal

## Why

Хвост «применить команду документа и синхронизировать окно» (закоммитить открытый текст, проверить живость выделения, погасить одноразовый инструмент, refit при смене размера базы, вытолкнуть состояние тулбара) собран вручную в шести местах `src/editor_window.rs` — проверка живости выделения скопирована дословно, и каждая новая точка входа копирует протокол заново. Заодно доступность листания ◄/► пересчитывается чтением папки (`read_dir` + stat каждого файла + сортировка) на каждой перерисовке — то есть на каждом тике драга и каждом нажатии клавиши, — а чтение `toolbar_state()` ещё и пишет обратно в ширину штриха, так что агентский `GET /state` мутирует состояние.

## What Changes

- Новый чистый модуль `src/editor/sync.rs` — **план синхронизации**: функция из производных фактов команды (создан ли элемент, размер базы до/после, живость выделения) в плоскую структуру решений `{ drop_tool, selection: Keep|Clear, refit }`, с юнит-тестами без окна.
- Один вход «применить и синхронизировать» на `EditorView`: безусловный пре-шаг (коммит открытого текста, no-op без поля), затем `before → apply → after → sync_plan`, исполнение плана в фиксированном порядке. Существующие точки (`handle_mouse_up`, `delete_selected`, `undo_redo`, `agent_command`, `commit_text_editor`, `commit_frame_edit`) остаются тонкими обёртками над входом, внешние сигнатуры не меняются.
- Гашение одноразового инструмента выводится из команды (`AddElement`), как обе существующие ветки уже делают.
- Новый модуль **списка снимков** (`ShotList`): владеет путём папки, кеширует листинг и позицию текущего снимка; интерфейс `set_current` / `neighbors()` / `page(delta)`. Кеш обновляется событийно — показ снимка, сохранение нового, листание. Вид теряет ivar `save_dir`; ввод-вывод уходит из пути перерисовки.
- Правило «ширина выделенного элемента становится шириной для новых» переезжает из read-пути `toolbar_state()` в исполнитель плана синхронизации — чтение состояния перестаёт мутировать.
- Термины «план синхронизации» и «список снимков» заносятся в `GLOSSARY.md`.

Поведение меняется только в одном ребре: доступность ◄/► при внешнем (вне приложения) изменении папки отражается при следующем событии, а не мгновенно — см. дельту спеки.

## Capabilities

### New Capabilities

(нет — новых способностей нет, это углубление существующих)

### Modified Capabilities

- `shot-editor`: в требовании «Листание снимков» появляется политика пересчёта доступности — кеш обновляется событиями приложения (показ снимка, сохранение, листание), внешние изменения папки отражаются при следующем таком событии; остальные сценарии требования сохраняются.

## Impact

- Код: `src/editor_window.rs` (основная перестановка), новые `src/editor/sync.rs` и модуль списка снимков, `src/editor/mod.rs` (подключение модуля).
- Спека: `shot-editor` — дельта одного требования.
- `GLOSSARY.md`: два новых термина.
- Доменные скилы `minisnap-editor` обновляются тем же change'ем (карта модулей пополняется).
- Внешние интерфейсы (MCP agent-канал, горячие клавиши, тулбар) не меняются; `GET /state` возвращает те же значения, но перестаёт мутировать ширину штриха.
