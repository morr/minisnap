# Design

## Context

`src/overlay.rs` (1841 строка на master@9ab7490) держит всю хореографию
HUD-слоёв в методах `OverlayView`: 13 полей слоёв в `OverlayIvars`,
`setup_hud`/`update_hud`/`update_dim`/`hide_hud`/`rebuild_border_path`/
`start_border_pulse`/`set_label_text`/`make_sampler`, HUD-вставки в шве
`present_target` (список 10 слоёв для `contentsScale`, перестройка пути
рамки, пересборка сэмплера) и мёртвый `line_brightness_in` «для тестов».
Шов `present_target`/`SurfaceMap` и конвенция `capture::geometry` (единственный
конвертер координат) установлены прошлым раундом и не пересматриваются.

## Goals / Non-Goals

**Goals:**

- Семья HUD (слои хрома + `FrameSampler`) живёт в одном модуле за одним
  interface'ом `Hud`; `OverlayView` управляет сессией, а не слоями.
- Новый HUD-слой не требует правок `present_target` — только кода модуля.
- Математика размещения лупы/подписи — чистая функция с юнит-тестами
  (флип у краёв, клэмп сэмпла, снап к целым пунктам).
- Наблюдаемое поведение оверлея не меняется: слои, их z-порядок, анимации
  (fade-in рамки, пульс, отключение неявных анимаций) переезжают как есть.

**Non-Goals:**

- Не менять шов `present_target`/`SurfaceMap` (форма прошлого раунда):
  тело сжимается заменой вставок на `hud.present(...)`, это углубление шва.
- Не менять публичный API `Overlay` (`show`/`is_active`/`cancel`/
  `poll_resolved_click`) и его единственного потребителя `src/app.rs`.
- Не трогать конвертеры координат: раскладка лупы зовёт
  `capture::geometry::display_point_to_logical_pixel`, новых формул не
  появляется.
- Не менять нормативное поведение HUD (спека `frozen-capture`).

## Decisions

1. **Файл модуля — `src/overlay_hud.rs`** (плановый вариант; альтернатива
   `src/overlay/hud.rs` отклонена: перевод `overlay.rs` в каталог-модуль
   переименовал бы файл ради одного переезда, все `use crate::overlay::*`
   и `mod overlay;` в `main.rs` остаются на месте). В `main.rs` добавляется
   `mod overlay_hud;`; `Hud` — `pub(crate)`.

2. **`Hud` владеет контейнером-слоем.** «`root_layer` получает ровно двух
   детей» реализуется контейнерным `CALayer`: root = `[frame_layer,
   hud.container]`, весь хром — дети контейнера в прежнем z-порядке
   (dim-полосы, оси, лупа, подпись, рамка). Координаты детей не сдвигаются:
   контейнер имеет origin `ZERO` и размер экрана, фреймы детей
   (дисплей-локальные пункты) остаются теми же. Альтернатива — вешать слои
   прямо в root и держать их список — вернула бы в view знание состава HUD.

3. **Interface `Hud`** (сигнатуры по коду, минимальные):

   - `Hud::new() -> Hud` — сборка и стилизация всех слоёв (`setup_hud` +
     `setup_strip`), элементы idle скрыты, путь рамки не строится (нечем —
     размер экрана неизвестен; его строит `present`).
   - `attach(&self, root: &CALayer, scale: f64)` — разовое цепление
     контейнера в root (вместо цикла dim-полос и `setup_hud` в
     `layers_attached`-блоке `show`), `contentsScale` по текущему масштабу.
   - `present(&self, scale: f64, screen: CGSize, frame: Option<(&CGImage,
     usize, usize)>)` — `contentsScale` всех слоёв, путь рамки, пересборка
     `FrameSampler` (кортеж: изображение + пиксельный размер), перезапуск
     fade-in/пульса рамки; внутри — тот же `CATransaction` с выключенными
     действиями для резких замен и отдельные транзакции для fade-in (как
     сейчас). Дополнительно запоминает `screen`/`scale` в `Cell` — см. п. 4.
   - `update(&self, cursor: CGPoint, selection_px: Option<(f64, f64)>)` —
     покадровое (бывший `update_hud` с `update_hud_inner`).
   - `dim(&self, hole: Option<CGRect>)` — бывший `update_dim`.
   - `hide(&self)` — бывший `hide_hud`.
   - `stop_border_pulse(&self)` — снятие пульса; покрывает оба места:
     `mouseDown` (рамка статична в протяжке) и `finish`.
   - `drop_sampler(&self)` — добавка к списку из шести методов: `finish`
     сегодня явно роняет `sampler` (десятки МБ на 5K-дисплей); прятать это
     в `hide()` нельзя — `present_target` зовёт `hide()` на idle-сбросе,
     где сэмплер жив. Альтернатива (оставить сэмплер в ivars view)
     разъединяла бы владельца данных и потребителя.

   Отклонение от эскиза решений: `update` не принимает `screen` — размер и
   масштаб запоминаются в `present()` (`Cell<CGRect>`/`Cell<f64>`), иначе
   `dim(Option<CGRect>)` из того же эскиза оставался бы без источника
   размеров. Данные те же, источник один — момент презентации.

4. **Чистое ядро** — свободная функция
   `loupe_layout(cursor, screen, scale, sampler) -> LoupeLayout`, где
   `LoupeLayout { loupe_frame, label_frame, sample_rect, cursor_logical }`.
   Тестам достаточно синтетического сэмплера (помощник `synthetic_frame`
   переезжает вместе с тестами сэмплера). Отклонение от эскиза: добавлен
   параметр `scale` — `geometry::display_point_to_logical_pixel` принимает
   масштаб и фактор сэмплера раздельно (при дробном backing scale фактор
   после `.round()` не равен масштабу), а `cursor_logical` возвращается
   структурой, чтобы текст подписи не считал конверсию второй раз. Тексты
   подписи (`"{} × {}"`) и `CATransaction`-обвязка остаются в `update()`,
   не в чистом ядре.

5. **`FrameSampler`** переезжает целиком (структура, `FrameSampler::new`
   вместо `OverlayView::make_sampler`, поля `width/height/factor`), внутри
   `overlay_hud.rs`, отдельный модуль не заводится — сэмплер без слоёв HUD
   бессмыслен (лупа читает только его). `line_brightness_in` и
   `LIGHT_CONTENT_THRESHOLD` не переезжают и удаляются: их единственные
   потребители — тесты сэмплера — переписываются на прямое чтение `buf`
   (левая/правая половина синтетического кадра), `#[allow(dead_code)]`
   уходит вместе с ними. Альтернатива «перенести в тестовый модуль» отклонена:
   тесту нужен не помощник продакшн-кода, а три строки чтения байтов.

6. **`CGBitmapContextCreate` — одна форма.** Extern-блок в `overlay.rs`
   (39–49) удаляется: после переезда сэмплера и его тестов в `overlay_hud.rs`
   пользователей в overlay.rs не остаётся; новый модуль импортирует
   конструктор из крейта `objc2_core_graphics`, как `capture.rs:12`.

7. **Пересчёт полей.** В решениях кандидата фигурировали «27 полей, 14
   HUD»; по коду их 34 и 13 (полный список: `dim_strips`, `loupe`,
   `loupe_grid`, `loupe_cross`, `loupe_frame_light`, `loupe_frame_dark`,
   `axis_v_dark/light`, `axis_h_dark/light`, `size_label`, `border`,
   `sampler`). После переезда `OverlayIvars` — 22 поля (13 уходят,
   добавляется `hud: Hud`). `screen_frame`/`scale` остаются в ivars view —
   это сессионное состояние (`rebuild_veils`, mouseUp, исход), модуль держит
   свои копии для раскладки.

8. **Компрессия `present_target`.** Порядок шагов сохраняется: `apply_target`
   → сброс в Idle (`hud.dim(None)` + `hud.hide()`) → транзакция с
   геометрией root/frame-слоя и подменой кадра → `hud.present(...)` →
   `rebuild_veils` → перенос окна → (fade-in/пульс теперь внутри present).
   Единственное смысловое изменение — fade-in рамки выполняется внутри
   `present` после транзакции подмены кадра, как и раньше по порядку.

## Risks / Trade-offs

- [Слои переезжают в контейнер — z-порядок/координаты могли бы поплыть] →
  порядок добавления детей контейнера совпадает с прежним порядком
  добавления в root; контейнер не клипует (`masksToBounds` по умолчанию
  false), лупа клипует сама. Live-проверка оверлея в тасках.
- [Анимации рамки чувствительны к порядку транзакций] → fade-in/пульс
  переезжают блоком, без перекомпоновки; `stop_border_pulse` остаётся
  простым `removeAnimationForKey`.
- [Двойное состояние `screen`/`scale` (ivars view + `Cell` модуля)] →
  записываются в одном месте — `present`, вызываемом из `present_target`
  сразу после `apply_target`; рассинхрон между ними невозможен до следующего
  `present`. Ценой осознанно куплена простота `dim`/`update`.
- [TCC сессионного билда] → live-проверка (лупа, протяжка, пульс, клик) при
  барьере помечается «ждёт ручной проверки», юнит-тесты чистого ядра
  остаются страховкой регрессии математики.

## Migration Plan

Три коммита по tasks.md (сэмплер → `Hud` целиком → чистое ядро с
тестами), каждый зелёный по `cargo build && cargo clippy && cargo test`.
Откат — обратный порядок коммитов; публичных API вне крейта нет.
