# Design

## Context

Слайдер — самописный `WidthSliderView` (`NSControl`) в `editor_toolbar.rs`: значение зажато в диапазон `STROKE_MIN=1.0..STROKE_MAX=12.0`, дорожка отображается на него линейно в `drag_to`/`knob_x`, каждое движение мыши уходит наружу как `ToolbarEvent::WidthChanged`. Окно в обработчике обновляет `stroke_width` и живо перекрашивает выделенный штриховой элемент (`apply_width`, тяга сливается в один undo-шаг). Синхронизация ручки — пуш `ToolbarState` из каждого `redraw` через `set_state` → `setDoubleValue:`; позиция ручки считается чистой редукцией `toolbar_state` (выделенный штриховой элемент зажимает ручку на своей толщине).

Кегль текста отдельного регулятора не имеет: `DEFAULT_TEXT_SIZE_PX = 32.0` в `editor/drag.rs`, поле `size` уже есть у `ElementKind::Text` и `Callout`, но командой журнала размер не является — `EditText` несёт только текст. Диапазон слайдера 1–12 кегль 32 не представляет в принципе, поэтому текстовому режиму нужен собственный диапазон.

Подгонка текстового блока существует только для коллаута: `callout_anchor` (в `editor/drag.rs`) ставит блок у основания против острия и зажимает его в кадр с отступом 4 px; при вводе `refit_callout_editor` перевызывает её через `controlTextDidChange`. Обычный текст не подгоняется нигде — ни при вводе, ни при коммите.

## Goals / Non-Goals

**Goals:**
- В текстовом режиме ввода слайдер размеров с собственной шкалой; ручка синхронна с кеглем.
- Живое обновление field-редактора: шрифт, рамка, переанкер коллаута, подгонка в кадр.
- Правка размера существующего текста как команда журнала со слиянием тяг и детерминированной подгонкой при реплее.

**Non-Goals:**
- Толщина указателя коллаута и штрихов при вводе текста не меняется (заморожена при рисовании по спеке).
- Смещение обычного текста при наборе символов (без смены размера) — поведение не трогается.
- Отдельная кнопка/регулятор размера текста не вводится — слайдер один, режимы у него.

## Decisions

**D1 — Шкала слайдера живёт в `ToolbarState`.** `ToolbarState` получает `slider_value: f64` и `slider_range: (f64, f64)` (переименование `stroke_width` → `slider_value`; событие `WidthChanged` → `SliderChanged` — слайдер теперь двуличный, имя «width» вводит в заблуждение). Редукция `toolbar_state` получает параметр `text_input: Option<f64>`: `Some(размер)` — значение равно размеру, диапазон текстовый; `None` — прежняя логика толщины. `WidthSliderView` хранит диапазон в ivars и отображает дорожку через него; `setDoubleValue:` зажимает в активный диапазон. `ToolbarView::set_state` протаскивает диапазон вместе со значением. Альтернатива — оставить поле `stroke_width` и класть в него кегль: отклонено, имя поля начнёт врать.

Числа диапазона: `TEXT_SIZE_MIN = 12.0`, `TEXT_SIZE_MAX = 96.0` рядом с `STROKE_MIN/MAX`; 32 (дефолт) внутри. Константы настраиваемые, в спеку не вынесены.

**D2 — Активный размер ввода — ivar окна.** `EditorIvars.text_size: Cell<f64>`; `begin_text_edit` ставит его (размер элемента для `Existing`, дефолт для `New`), коммит `New` читает. Альтернатива — поле в `TextTarget::New`: отклонено, `TextTarget` — словарь машины драга, мутировать сигнал посреди ввода значит протаскивать UI-заботу в машину.

**D3 — Ветвление в обработчике слайдера.** `SliderChanged` в окне: если `text_editor` занят — текстовая ветка, иначе прежняя толщинная. Текстовая ветка по `text_target`: (а) `New { callout: true }` — машина получает `set_pending_callout_size(size, image)`, обновляющий `PendingCallout.size` и возвращающий переанкеренную позицию блока (та же `callout_anchor`), поле `setFrame` по ней, шрифт обновить; (б) `New` обычный — шрифт + рамка по `text_editor_frame(origin, text, size)` с зажимом в кадр; (в) `Existing { id }` — `shot.apply_text_size(id, size)` (слияние тяг как у `apply_width`) + шрифт + рамка по обновлённому элементу. В текстовой ветке `stroke_width` ivar не трогается — ручка вернётся к толщине на следующем `set_state`. Замечание по займам: размер кадра (`image_size`) читать до `shot.borrow_mut()` — двойной заём того же `RefCell` паникует (грабли из рефакторинга 41e1b22, починены сегодня).

**D4 — Команда `SetTextSize(id, size)` с подгонкой внутри `apply_cmd`.** В `editor/mod.rs`: новый вариант команды; `apply_cmd` меняет `size` у `Text`/`Callout` и зажимает блок в кадр — чистая функция `clamp_block(origin, w, h, frame) -> Point` (минимальный сдвиг, отступ 4 px — общий с `callout_anchor`), кадр берётся из размеров базы `DocState`. Зажим внутри `apply_cmd`, а не в окне — реплей журнала воспроизводит сдвиг без хранения его в команде; уменьшение размера после сдвига не отскакивает (зажим текущей позиции при новом меньшем блоке — no-op). `EditorDoc::apply_text_size` и `OpenShot::apply_text_size` — зеркала `apply_width`/`Session::apply_width` с тем же правилом слияния. Альтернатива — отдавать сдвиг отдельной `MoveElement`-командой: отклонено, два undo-шага на одну тягу и риск рассинхрона окна и реплея.

**D5 — Подгонка коммита нового текста.** Ветка `New` в `commit_text_editor`: обычный текст — `origin` пропускается через `clamp_block` перед `AddElement`, размер из `ivars.text_size`; коллаут — без изменений, `commit_callout_text` уже меряет и анкерит по `pending.size`, обновлённому тягой. Правка `Existing` в коммите не меняется: команды размера уже легли в журнал при тяге, `EditText` несёт только текст.

**D6 — Refit при смене размера.** `refit_callout_editor` остаётся хуком `controlTextDidChange`; текстовая ветка слайдера вызывает нужные обновления сама (шрифт + рамка/переанкер). В `refit_callout_editor` ветка `Existing` дополняется зажимом `clamp_block` — при росте кегля авторская позиция сохраняется, пока блок влезает, при невлезании сдвигается.

## Risks / Trade-offs

- [Реплей обязан совпасть с живой подгонкой] → зажим только внутри `apply_cmd`/общей функции; окно для рамки поля считает позицию той же функцией, ничего не запоминает.
- [Расхождение шрифта поля и рендера] → та же конвертация, что в `begin_text_edit`: pt = px × масштаб вида, минимум 9 pt; при мелких масштабах поле покажет 9 pt, элемент останется в px — существующее поведение, не расширяется.
- [Скачок ручки при входе/выходе текстового режима] (4 → 32 и обратно) → задумано; переключение режима синхронно с событиями мыши/клавиатуры, гонок нет.
- [Версионный skew журнала] → `SetTextSize` в `commands.json` старый бинарь не прочтёт; свойство любого добавления команды, не усугубляется.
- [Юнит-тесты] → редукция `toolbar_state` (текстовый режим: значение+диапазон; толщинный не изменился; зажим выделения в текстовом режиме не срабатывает), `apply_cmd::SetTextSize` (размер, зажим, отсутствие отскока), слияние тяг, `set_pending_callout_size` — без окна.

## Migration Plan

Не требуется: журнал аддитивен, сессии без `SetTextSize` реплеятся как раньше. Откат — реверс коммитов, новые сессии с командой размера старым бинарём не читаются (см. риски).
