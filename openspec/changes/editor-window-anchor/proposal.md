# Proposal

## Why

При листании снимков кнопками ◄/► окно редактора каждый раз заново центрируется: `display_shot` → `refit_window` → `window.center()` (`src/editor_window.rs`). Размер окна подгоняется под пиксели снимка, поэтому у соседних снимков разного размера центр разный — левый верхний угол окна прыгает при каждом переключении. Тот же `refit_window` вызывают применённые кроп и ресайз: смена размера кадра тоже сдвигает окно. Прыгающее окно сбивает ориентацию при переборе кадров и при правке размера базы.

## What Changes

- `refit_window` перестаёт центрировать окно при каждой подгонке. Центрирование остаётся только для первого показа окна; все последующие подгонки размера (листание ◄/►, применённый кроп, применённый ресайз) сохраняют положение левого верхнего угла окна, меняя только размер (высота растёт/убывает вниз, ширина — вправо).
- Никаких новых сущностей и настроек: правка одного метода плюс флаг «окно уже размещено». Поджим окна обратно в экран не добавляется: окно держится за угол, даже если новый край выходит за пределы экрана.

### Modified Capabilities

- `shot-editor`: добавляется требование «Позиционирование окна под снимок» — первое открытие центрирует окно на экране, последующие подгонки размера под новый снимок или новый размер кадра не сдвигают левый верхний угол.

## Impact

- `src/editor_window.rs`: `refit_window` (якорь за левый верхний угол вместо `center()`) и один ivar-флаг.
- Домен-скилл `minisnap-editor`: `references/window-mechanics.md` описывает текущее поведение («…и центрирует окно») — синхронизируется в этом же change.
- Параллельный change `editor-system-titlebar` (в полёте, пока только proposal) переписывает в этой же capability требование «Окно редактора»; дельта этого change'а сделана отдельным ADDED-требованием и с ним не пересекается.
