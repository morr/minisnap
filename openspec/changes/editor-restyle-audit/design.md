# Design

## Подход

Аудит без смены стека: каждая правка — точечная замена конкретного визуального решения в `src/editor_window.rs`, поведение (target/action, журнал команд, хит-тесты) не трогается. Каждое решение рестайла сверено с базой `ui-ux-pro-max` (домены `ux`, `icons`, `color`) и чек-листом `references/pro-rules.md`; вердикты — ниже, полная таблица в итоговом отчёте.

## Вердикты аудита и решения

### Анимации состояний (заменено)

- База: анти-паттерн «Instant state changes (0ms)» (категория Interaction, приоритет 2); правило «Duration Timing» не задаёт универсального порога — «Don't present 150-300ms as a universal requirement», главное — отзывчивость фидбека. Правило «Reduced Motion» (High) требует учитывать настройку движения.
- Реализация: обёртка смены фонов слоёв в `NSAnimationContext` (`beginGrouping` → `allowsImplicitAnimation` + `duration 0.15` → `endGrouping`) — штатный путь анимации layer-свойств layer-backed view. Гейт: `NSWorkspace.sharedWorkspace().accessibilityDisplayShouldReduceMotion` — при включённой настройке смена мгновенная. Конфликтующие анимации заменяются CA автоматически (правило «Cancellable State Transitions»), целевое состояние ставится напрямую, ничего не зависит от завершения анимации.
- Анимируются только фоны плашек (`backgroundColor`); смена `contentTintColor` символа при выборе инструмента — не layer-свойство, остаётся мгновенной.

### Имена доступности и подсказки (заменено)

- База: «give the control an accessible name and expose applicable state» (иконочное правило, домен `icons`); pro-rules «Contextual Semantics».
- Сейчас `accessibilityDescription` у SF-символов — внутреннее имя (`arrow.up.right`), у кнопок тулбара пустой заголовок: вспомогательные технологии не смогут назвать кнопку.
- Реализация: человеческие подписи (`accessibilityLabel`) и `toolTip` на всех кнопках (◄/►, свотч, 9 инструментов); `accessibilityDescription` символов — тот же человеческий текст. Требуется фича `NSAccessibility`.

### Свотчи: размер, hover, обводка (заменено)

- Размер: правило «Target Size (Minimum)» (High) — 24×24 для курсорных целей (кнопки 26 pt уже проходят, свотчи 20 pt — нет).
- Hover: правило «Hover States» (Medium) — «No hover feedback on clickable elements» — свотч сейчас единственный контрол без отзыва; подменять заливку белым нельзя (это сам цвет) — hover выражается подсветкой обводки.
- Обводка: pro-rules «Icon Contrast» — границы контролов ≥ 3:1; `separatorColor` на тёмном HUD ≈ 2.2:1, белый 50% ≈ 3.4:1 — держит и чёрный пресет. Обводка 1 pt сохраняется.

### Подтверждено базой (оставлено)

- Активный инструмент: акцентная плашка 25% + тон акцентом — «Active State» (Medium): активный элемент выделяется цветом.
- Неактивные символы белый 90% на тёмном HUD — pro-rules «Icon Contrast» ≥ 3:1: фактический контраст ≈ 9:1; pro-rules «Text contrast (dark) ≥ 4.5:1» — secondaryLabel имени файла на HUD ≈ 5.6:1.
- Материал `.hudWindow`: правило «Color Contrast 4.5:1» выполняется на тёмном материале; конвенция macOS — HUD-материал именно для плавающих панелей поверх контента.
- Кнопки 26 pt и спейсинг 6 pt: «Target Size» для курсорного ввода — 26 ≥ 24; правило «Touch Spacing» (8 px) — тач-минимум, не для курсора.
- Слайдер: вся область 90×24 кликабельна (≥ 24); трек/ручка — нет данных в базе, конвенция AppKit-слайдеров.
- Радиусы 12, тёмный appearance принудительно, `ByTruncatingMiddle` имени файла: нет данных в базе, конвенции macOS (HUD поверх контента, одна тема для стабильного контраста — pro-rules «State contrast parity»).

### Зафиксированный разрыв (не правится в этом change)

- Фокус-ринг: база требует видимый фокус на каждом контроле (High), но все кнопки тулбара `refusesFirstResponder` осознанно — клавиши остаются на канве, модель ввода редактора. Полноценная клавиатурная навигация по тулбару (с учётом Full Keyboard Access) — отдельное решение вне хрома; в design рестайла это было явно (комментарий в коде). Для пользователя это выносится в список ручной проверки.

## Токены

Разрозненные альфы собираются в константы рядом с существующими (`ICON_TINT`, `HOVER_BG`): `ACTIVE_WASH` (акцент 0.25), `TRACK_UNFILLED` (белый 0.22), `KNOB_SHADOW` (чёрный 0.35) — design-system: семантическое имя и комментарий-назначение у каждого токена. Заголовок OK — `boldSystemFontOfSize` 13 (конвенция дефолтной кнопки: Enter подтверждает рамку).

## Риски

- `allowsImplicitAnimation` анимирует не все layer-свойства в конфигурациях AppKit; проверка на первом прогоне — если кроссфейд не подхватывается, длина анимации не критична (единственная альтернатива — явные CABasicAnimation, неоправданно для 150 мс). Не анимируется — состояние всё равно корректно.
- Свотч 24 pt в тулбаре визуально крупнее глифов 15 pt — намеренно: круг цвета сам по себе крупнее линии глифа; проверяется глазами.
