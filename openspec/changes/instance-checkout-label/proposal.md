# Proposal

## Why

Инстансы minisnap, запущенные из основного чекаута и из worktree'ов, неразличимы ни на экране, ни в трее: одна иконка, одинаковые меню и окна, общий конфиг. Агенты, ведущие работу в worktree'ах, путают запущенные инстансы, и AGENTS.md вынужден держать процедуру опознания по пути бинарника через `ps`. Если инстанс сам называет свой чекаут, опознание становится тривиальным — для человека (меню, tooltip, заголовок настроек), для агента (скриншот, вывод stderr при запуске).

## What Changes

- При старте инстанс выводит из пути исполняемого файла метку чекаута: путь под `.worktrees/<branch>/…` даёт метку `<branch>`, любой иной путь — метку `main`.
- Метка появляется в трей-меню первым некликабельным пунктом «minisnap — <метка>» с разделителем после него и в tooltip'е иконки трея тем же текстом.
- Заголовок окна настроек становится «Preferences — <метка>».
- При запуске в stderr печатается одна строка с меткой и путём исполняемого файла.
- Внешняя идентичность бандла не меняется: имя бинарника, Info.plist, код-подпись и путь конфига остаются прежними.

## Capabilities

### New Capabilities

- (нет)

### Modified Capabilities

- `tray-app`: новое требование — метка чекаута инстанса в трей-меню и tooltip'е иконки, плюс строка в stderr при запуске.
- `preferences`: новое требование — заголовок окна настроек с меткой чекаута.

## Impact

`src/app.rs` (вывод метки из пути, заголовочный пункт меню, tooltip, строка в stderr), `src/prefs.rs` (заголовок окна; `build` принимает метку). Скилл `.zcode/skills/minisnap-shell/SKILL.md` и раздел «Working with a running app» в AGENTS.md обновляются в том же change'е. Разрешения не затрагиваются: подпись и идентичность бандла не меняются, TCC-грант Screen Recording сохраняется.
