# Design

## Context

Сейчас `capture_t0` (`src/capture.rs`) фиксирует только дисплей под курсором: `shareable_content` → `pick_display` → `capture_display_image`. `Overlay::show` (`src/overlay.rs`) показывает кадр на этом дисплее и вешает вуали (`make_veil`) на остальные экраны; `handle_mouse_moved` клампит курсор к границам дисплея, поэтому переход курсора на соседний монитор ничего не меняет до конца режима. Список окон T0 — глобальный (SCKit-фреймы окон не привязаны к дисплею), и клик-по-окну уже умеет хит-тестить в глобальных координатах.

Ключевой факт AppKit: события `mouseMoved` доставляются ключевому окну независимо от того, где курсор. Оверлей — key window на всё время режима, значит он и над вуалью соседнего дисплея продолжает получать перемещения; глобальную позицию даёт `NSEvent::mouseLocation()`. Отдельного слежения за курсором (глобальные мониторы событий, таймеры) не требуется.

## Goals / Non-Goals

**Goals:**
- Переключение цели захвата за курсором без повторного захвата и без новых асинхронных путей.
- Сохранение контракта T0: всё, что видит и вырезает пользователь, — из кадров, зафиксированных при нажатии хоткея.
- Выходной конвейер (`output::crop`, буфер, файл, редактор) не меняется.

**Non-Goals:**
- Живое (незамороженное) содержимое на нецелевых дисплеях.
- Параллельный захват дисплеев, ленивый дозахват при входе на дисплей.
- Новые настройки, хоткеи, индикаторы «на каком дисплее я».

## Decisions

### 1. Все кадры фиксируются в T0, последовательно

`capture_t0` после единственного `shareable_content` снимает `capture_display_image` для каждого `SCDisplay` из `content.displays()` в том же фоновом потоке и собирает набор поверхностей. Цель — дисплей под курсором, как сейчас.

Альтернативы:
- *Ленивый захват при входе на дисплей (T1)* — отклонён: нужен новый асинхронный путь (запрос из оверлея → фон → `mpsc` → тик → обратный вызов в оверлей), защита от гонки «курсор ушёл до завершения захвата», и на ~150–300 мс переключения вуаль-заглушка висит на целевом дисплее. Экономия — ~60 МБ на кадр и разовая работа за хоткей; сложности не окупают.
- *Параллельный захват (поток на дисплей)* — отклонён: `Retained<SCDisplay>`/`SCShareableContent` не `Send`, потребовались бы unsafe-обёртки вокруг objc2-объектов. Последовательный захват сохраняет конвенцию «захват — в фоновом потоке, результат через `mpsc` в тик» без новых видов потоков.

### 2. Поверхности — в `T0Capture`, сопоставление с экранами — в `show()`

`T0Capture` превращается в `{ target: usize, windows, surfaces: Vec<T0Surface> }`, где `T0Surface { image, display_frame_sckit }` — кадр и SCKit-фрейм одного дисплея; `target` — индекс поверхности под курсором (выбирает `pick_display`, как сейчас). `Overlay::show` принимает его целиком, хранит `surfaces` в ivars и на главном потоке сопоставляет поверхности с `NSScreen::screens`: SCKit-фрейм дисплея переводится в AppKit-пространство флипом по `primary_screen_height` и сверяется с `NSScreen.frame` с допуском ~1 pt; `scale` берётся с найденного экрана (`backingScaleFactor`). Сравнивать только размеры нельзя — два одинаковых монитора неразличимы; сверяются целые фреймы (origin + size). Поверхность без пары-экрана не участвует в переключении (экран под вуалью навсегда).

`image`, `display_frame_sckit`, `screen_frame`, `scale` остаются «плоскими» полями ivars (их читают `handle_mouse_up`, `update_hud`, `finish`) и подменяются при переключении — поэтому `finish()` и выходной конвейер не меняются: результат всегда собирается из кадра той поверхности, которая была текущей в момент завершения.

### 3. Курсор на чужом дисплее — по `mouseLocation` в `mouseMoved`

В `handle_mouse_moved` (только `Idle`): `NSEvent::mouseLocation()` → экран из `NSScreen::screens`, содержащий точку; если это не текущая цель — переключение, иначе прежний путь (лупа, оси). Во время `Drag` метод выходит рано — переключений в протяжке нет, прямоугольник по-прежнему ограничивается краем дисплея (и dragged-события всё равно идут окну, начавшему протяжку).

Альтернатива — `NSEvent::addGlobalMonitorForEvents` — отклонена: глобальный монитор получает события других приложений, для своих нужен локальный монитор, и в сумме это второй механизм там, где уже работающий `mouseMoved`.

### 4. Переключение — синхронная пересборка содержимого окна

Новый метод `OverlayView` (условно `switch_to_surface`): `setFrame_display` на AppKit-фрейм новой цели, подмена `frame_layer.contents` + `contentsScale`, пересборка `FrameSampler`, сброс состояния (`Idle`, скрыть лупу/оси/лейбл, `update_dim(None)`), пересоздание вуалей (все `orderOut`, набор — все экраны минус новая цель), перезапуск fade-in и пульса рамки, `makeKeyAndOrderFront`. Повторный вход защищён теми же `active`/`finishing`, что и `show`.

Вуаль-клик (отмена) сохраняется как запасной путь: при обычном переходе курсора `mouseMoved` переключает цель раньше `mouseDown`, и вуаль на этом дисплее уже снята; клик по вуали достижим, только если курсор оказался на дисплее без промежуточных событий перемещения (телепорт указателя, виртуальная машина). Конфликта с переключением нет.

### 5. Клик-по-окну работает на любой цели без изменений

Хит-тест клика идёт в SCKit-глобальных координатах по глобальному списку окон T0: `display_frame_sckit` + локальная точка → глобальная точка → `topmost_window_at` → `window_frame_to_pixel_rect` с клампом к кадру текущей цели. Все переводы — через существующий `capture::geometry`; новых конвертеров не нужно.

## Risks / Trade-offs

- [Латентность старта растёт с числом дисплеев: ~+100–200 мс на каждый дополнительный] → это цена мгновенного переключения; если станет заметна, оптимизируется отдельным change (параллельные потоки с `unsafe Send`-обёртками или ленивый захват при первом входе).
- [Память: все кадры T0 живут до конца режима, ~60 МБ на 5K-дисплей] → освобождается в `finish()` вместе с текущим кадром; для интерактивного режима приемлемо.
- [Дробные расхождения между AppKit- и SCKit-фреймами при сопоставлении дисплеев] → сравнение с допуском; несовпавший дисплей не получает поверхность и остаётся под вуалью (поведение «дисплей без кадра T0» из спеки).
- [Пересборка `FrameSampler` при переключении — короткий (~десятки мс) подлагивание] → переключение редкое действие; при заметности — собирать сэмплер лениво при первом `mouseMoved` на новой цели.
- [`mouseMoved` зависят от key-статуса окна оверлея] → уже обеспечивается существующей активацией в `show()` (`activateIgnoringOtherApps` + отложенный `makeKeyAndOrderFront`); переключение наследует механизм, ничего нового не добавляет.
