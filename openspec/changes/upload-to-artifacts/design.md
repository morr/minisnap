# Design

## Context

Сервер artifacts принимает изображения через `PUT /api/images/{name}`: тело — байты PNG, заголовки `Authorization: Bearer <токен>`, `Content-Type: image/png`, опциональные `X-Project: <slug>` (namespace проекта) и `X-Create-Only: true` (409 вместо перезаписи существующего). Успех — 201/200 c JSON, среди полей которого `url` (публичный адрес изображения с расширением). Имя и проект валидируются сервером правилом `^[a-z0-9][a-z0-9-]{0,63}$`. Файл снимка уже поддерживается актуальным: `OpenShot::persist` атомарно перезаписывает PNG после каждой правки, поэтому загрузчик всегда читает текущее состояние снимка с диска.

Сетевых крейтов в проекте нет; agent-сервер — собственный HTTP-листенер поверх std::net. Асинхронные результаты доезжают до главного потока через `mpsc` (`MainJob`) и перекачиваются тиком — этот же канал обслужит и загрузку.

## Goals / Non-Goals

**Goals:** загрузка файла снимка на artifacts-сервер из редактора и из нового действия захвата; URL в буфере по успеху; читаемые ошибки; настройка токена/проекта в UI настроек; без новых Rust-зависимостей.

**Non-Goals:**
- Автоматическая загрузка каждого захвата (галочка) — отложено; возможный следующий change (просьба всплывала при explore редактора, в скоуп обещанного change не входит).
- Программный запуск загрузки через агентский канал (`agent-control`) — отдельное расширение.
- Drag-out URL, индикатор прогресса с процентами, очередь загрузок (повторный клик во время загрузки игнорируется).
- Выбор проекта/адреса на лету в UI: адрес — только конфиг, проект — поле настроек.

## Decisions

### HTTP-клиент: системный NSURLSession, не Rust-крейт
`NSURLSession` + `uploadTask` через objc2-foundation (фича `NSURLSession`) и block2 (комплишн-блок уже в проекте). Альтернатива `ureq`/`reqwest` — синхронный вызов на потоке и новые деревья зависимостей с TLS; системный стек TLS и нативная асинхронность бесплатны. Комплишн-блок уходит в фоновую очередь сессии и отправляет `MainJob::UploadFinished` в тот же `mpsc`, что и захват. Запасной ход, если биндинги NSURLSession окажутся дырявыми: `ureq` с rustls — изоляция той же границы `upload.rs` позволяет поменять транспорт, не трогая остальное.

### Граница: новый модуль `src/upload.rs`
Весь сетевой код и код ответа — в одном модуле: `upload_file(path, &UploadConfig, jobs_tx)` (спавнит запрос, отправляет `MainJob::UploadFinished { result: Result<String, String> }`), чистые `upload_name(shot_file_stem) -> String` (строка имени, юнит-тесты) и разбор JSON ответа (`url` из 201/200). AppKit-вызовы (диалог ошибки, буфер) — в `app.rs`; `upload.rs` AppKit не трогает, кроме NSURLSession-объектов. Мост между редактором и приложением — колбэк, инжектированный в `EditorWindow` при создании (`on_upload(shot_path)`); состояние назад — `EditorWindow::set_uploading(bool)`, который пушится в `ToolbarState` (чистая редукция получает поле `uploading`), и тулбар рисует кнопку в состоянии загрузки (плитка из `plates.rs`).

### Имена загрузок
`MiniSnap_YYYY-MM-DD_HH-MM-SS[@<n>x][_N]` → `shot-YYYY-MM-DD-HH-MM-SS`: префикс `MiniSnap_` меняется на `shot-`, маркер плотности и суффикс локальной коллизии отбрасываются — локальный суффикс `_2` означает «та же секунда», что на сервере разрешается своим суффиксом `-2`. Правка существующего снимка (имя с датой создания, не правки) даёт стабильное имя — повторная загрузка того же снимка попадает в 409 и уходит в `-2`; это осознанная цена create-only: сервер никогда не теряет чужое изображение.

### Create-only с повтором
Каждый PUT несёт `X-Create-Only: true`; ответ 409 → повтор с `-2`, `-3`, … до `-9`, дальше ошибка «имена исчерпаны». Альтернатива — перезапись без флага: проще, но молча уничтожает существующее изображение сервера; отклонено.

### Действие захвата: bool → перечисление
`MainJob::CaptureReady { edit }` и путь `start_capture(edit)` растут третьим режимом — вместо второго bool вводится `CaptureKind { Plain, Edit, Upload }` (агентский `Capture { edit }` маппится: `true → Edit`). Ветвь `Selected` при `Upload` идёт по обычному конвейеру и после `save_to_file` зовёт `upload::upload_file`; `OpenEditor` посылается с `only_if_visible: true` как при обычном захвате. «Голая» сумма bool'ов здесь ещё держалась бы, но третья ветка делает перечисление честнее.

### Конфигурация
Новые поля `Config`: `upload_base_url: String` (`https://artifacts.spacehubstore.com`), `upload_token: String` (пусто), `upload_project: String` (`minisnap`), `capture_upload_hotkey: HotKey` (`⌘⌥6`). TOML-ключи — `upload-base-url`, `upload-token`, `upload-project`, `capture-upload-hotkey` (стиль существующих). Токен хранится в том же локальном TOML открытым текстом — принятая цена: файл вне репозитория, права доступа домашнего каталога; шифрование не предусмотрено. Настройки правят токен и проект через `Config::save_to` сразу при вводе; миграция легаси не нужна (новые ключи).

### Обратная связь
Успех: URL — в буфер обмена (хелпер рядом с `copy_to_pasteboard` в `output.rs`), для capture & upload это заменяет изображение снимка в буфере. Ошибка: `NSAlert` с текстом из главного потока при обработке `UploadFinished` тиком (единый путь для кнопки и хоткея; прецедент — модальный диалог разрешения). Токен не настроен: действие не отправляет запрос и показывает диалог «укажите токен в настройках».

### Тулбар
Кнопка Upload — последний контрол ряда (после разделителя за инструментами); событие `ToolbarEvent::UploadRequested`; состояние — поле `uploading` в `ToolbarState` (кнопка неактивна для повторных кликов, плитка показывает процесс). Минимальная ширина окна пересчитается сама — полоса должна вмещаться целиком по действующему требованию.

## Risks / Trade-offs
- Биндинги `NSURLSession` в objc2-foundation могут потребовать дополнительных фич/ручного месседжа — изолировано в `upload.rs`, запасной ход `ureq` описан.
- Модальный алерт на фоновую ошибку может застигнуть пользователя за работой в другом приложении — для v1 принят (ошибка должна быть видимой); если станет шумным — переосмыслить на нотификацию отдельным change.
- Токен открытым текстом в конфиге — компромисс локального инструмента; в лог и агентский канал он не выводится (инвариант тестируется чтением `/state` и `/log`).
