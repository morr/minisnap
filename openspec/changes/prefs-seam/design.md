# Design

## Context

`PrefsWindow` (`src/prefs.rs:81–109`) — публичные AppKit-контролы; поведение в `AppController`: `open_prefs_window` (~933, wiring), `update_prefs_row_titles` (~1241), `upload_fields_changed` (~1287), `upload_provider_toggled` (~218), `finish_recording` (~1200). Применение хоткеев дублировано: `AppController::new` (~512–526) и `finish_recording` (~1215–1230). Key-монитор ставится один раз на процесс (`app.rs:548`), хотя нужен только во время записи. `UPLOAD_PROVIDERS` — статический реестр, из которого `build` берёт `[0]`. Прецедент шва: `ToolbarView` в `editor_toolbar.rs`.

## Goals / Non-Goals

**Goals:**
- Поведение окна настроек живёт в `prefs.rs`; интерфейс — события наружу, снимок состояния внутрь.
- Применение хоткеев — один метод контроллера.
- Окно не знает `Config`; контроллер не знает устройство контролов.

**Non-Goals:**
- Не меняем состав и вид окна, поведение записи комбинаций (спека `preferences` неизменна), формат конфига.
- Не трогаем машину рекордера (`hotkey_recorder.rs`) — она уже чистая и протестированная.
- Не вводим реестр провайдеров — второй провайдер вернёт его в день появления.

## Decisions

### Шов: `PrefsState` / `PrefsEvent`, как у тулбара

`set_state(PrefsState)` на входе: четыре комбинации (или «Press keys…» для записывающей строки), состояние галочки, значения трёх полей, видимость секции. `PrefsEvent` на выходе: `RowClicked(row)`, `CombinationRecorded { row, hotkey }`, `RecordingCancelled(row)`, `ProviderToggled(bool)`, `FieldsChanged { token, project, proxy }`. Альтернатива — перенос только перерисовки заголовков — отвергнута на разборе: расщеплённый мозг остаётся.

Окно владеет `Recorder`-машиной (сейчас её держит контроллер): клик строки → `begin(row)` → установка монитора → события клавиш кормят машину → исход уходит событием наружу. Машина рекордера остаётся чистым модулем без AppKit — переезжает только её владелец.

### Монитор живёт со записью

`NSEvent.addLocalMonitorForEventsMatchingMask` ставится в `begin(row)` и снимается в конце записи (фиксация/отмена). Вне записи монитор не существует — сегодняшнее поведение «пропускать всё» становится отсутствием фильтра, наблюдаемо одинаково. Убирается ivar `monitor` из `AppController`.

### `apply_hotkeys(config)` — метод контроллера

Последовательность «перерегистрировать `HotkeyRegistry`, обновить key equivalent четырёх пунктов меню» собирается в один метод; `new` и обработка `CombinationRecorded` вызывают его. Отдельный модуль-владелец пунктов меню отвергнут: меню строится контроллером, третьего владельца не нужно.

### Конфиг у контроллера, окно докладывает

`FieldsChanged` приходит при каждом нажатии (как сегодня `controlTextDidChange`); контроллер решает, изменилось ли значение, и сохраняет. Галки и комбинации — так же. Окно не сохраняет ничего само.

## Risks / Trade-offs

- [Окно теряет фокус/key-статус при переносе wiring] → Порядок `prefsWindowToFront` не меняется; регресс на живом приложении (открытие из меню при открытом меню).
- [Монитор снимается, а событие уже в полёте] → Снятие монитора в том же цикле событий, что и фиксация; событие фиксации обрабатывается до снятия (порядок внутри обработчика), тест на живом приложении.
- [Дрейф сохранения полей при каждом нажатии] → Логика сравнения и записи переносится дословно; проверка логом (`prefs:` строки) до/после.

## Migration Plan

`prefs.rs` получает состояние и события первыми (интерфейс), затем переносится поведение строк, следом — секция загрузки, последним контроллер худеет и получает `apply_hotkeys`. Каждый шаг — зелёная сборка; откат — revert change.
