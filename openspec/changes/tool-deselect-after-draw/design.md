# Design

## Context

Состояние активного инструмента живёт в окне (`EditorView`, ivar `tool: Cell<Option<Tool>>`); тулбар состояния не держит — кнопка нажата, пока `toolbar_state()` (чистая редукция при каждом `redraw()`) видит `Some(tool)`. Команду создаёт машина драга (`DragMachine`, `editor/drag.rs`) и отдаёт окну в `DragOutcome.command`; элемент создаёт единственный вариант журнала — `Command::AddElement`. Применений команды в окне три (`src/editor_window.rs`): `handle_mouse_up` (протяжка), `commit_text_editor` (фиксация текста/коллаута — общий путь мыши и агента), `commit_frame_edit` (кроп/ресайз — уже сбрасывает инструмент). Агент применяет команды через `agent_command` мимо мышиных путей и ставит инструмент явно через `agent_set_tool`.

Мотивация — в proposal.md (Why); нормативное поведение — в specs/shot-editor/spec.md.

## Goals / Non-Goals

**Goals:**
- После фиксации элемента инструмент снимается: `tool` → `None`, кнопка отжимается, редактор в режиме просмотра.
- Единое правило для всех семи рисующих инструментов, включая двухфазные текст и коллаут (отжим — по созданию элемента, то есть по фиксации непустого текста).
- Жест без созданного элемента инструмент сохраняет.

**Non-Goals:**
- Agent-API не меняется: `agent_set_tool` остаётся явной установкой, `agent_command` инструмент не трогает.
- Машина драга (`editor/drag.rs`) не меняется и про тулбарное состояние ничего не узнаёт.
- Кроп/ресайз не трогаем — их отжим после применения уже реализован.

## Decisions

1. **Сброс по типу команды, в двух точках фиксации окна.** В `handle_mouse_up` и `commit_text_editor` после применения команды: если это `Command::AddElement(_)` — `ivars.tool.set(None)` перед `redraw()`. Редукция `toolbar_state` сама отожмёт плитку через существующий `set_state` — нового API тулбара не нужно.
   - Альтернатива «сброс на каждый mouse-up» — отвергнута: клик короче порога убил бы инструмент.
   - Альтернатива «машина сигналит о конце рисования» — отвергнута: машина чистая и без AppKit, инструмент — состояние окна/тулбара; команда `AddElement` уже есть в исходе, сигнала не требуется.
2. **Критерий — созданный элемент, а не «было взаимодействие».** `AddElement` из mouse-up покрывает стрелку, прямоугольник, линию, pen, блюр; `AddElement` из `commit_text_editor` покрывает новый текст и коллаут (пустая фиксация даёт `None`, правка существующего — `EditText`/`DeleteElement` — отжима нет). Правило совпадает со сценариями дельты спеки один в один.
3. **Сброс до `redraw()`, независимо от исхода `apply`.** Ошибка persist не откатывает команду (инвариант домена), значит элемент создан — инструмент отжимается.
4. **Порядок с существующими поведениями сохраняется:** при mouse-up с `Signal::BeginText` (коллаут, фаза 2) команда ещё не создана — кнопка остаётся нажатой на время ввода; отжимает её последующий `commit_text_editor`.

## Risks / Trade-offs

- [Многократное рисование подряд требует клика по кнопке перед каждым элементом] → Это и есть запрошенное поведение; возврат в режим просмотра между жестами даёт перенос окна и выбор элементов без переключений вручную.
- [Агентский путь текста идёт через `commit_text_editor` — после агентского текста/коллаута `state` покажет `tool: null`, если агент ставил инструмент] → Приемлемо: агент видит это в `state` и переустанавливает инструмент явно; документируем в скилле `minisnap-editor` при apply.
- [Забытый сброс в новой точке фиксации (будущие инструменты)] → Правило локализовано: элемент создаёт только `AddElement`, и обе не-агентские точки его применения уже покрыты; чекбокс в tasks.md — проверить, что новых точек apply нет.

## Migration Plan

Одно приложение, отката-миграции не требует (нет данных и формата); откат — ревертом коммита.
