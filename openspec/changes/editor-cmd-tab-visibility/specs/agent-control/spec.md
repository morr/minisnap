# Spec Delta

## MODIFIED Requirements

### Requirement: Состояние приложения

`GET /state` SHALL возвращать полное состояние в главном потоке: открыт ли редактор, оверлей, окно prefs; кадры собственных окон; состояние документа редактора — путь снимка, имя файла, элементы (id, вид, геометрия), выделение, активный инструмент, цвет и толщина для новых элементов, значения undo/redo; конфиг — хоткеи, каталог сохранения, retention; текущая политика активации приложения (`regular`, пока окно редактора видно; `accessory` — пока оно скрыто). Пока оверлей активен, состояние SHALL показывать это; пока редактора нет, документная часть SHALL быть пустой, а не ошибкой. Пока открыт текстовый ввод, состояние SHALL показывать рамку field editor'а (`text_editor_frame`, в пикселях кадра, origin top-left) и его содержимое (`text_editor_text`), чтобы геометрические проверки шли из состояния без скриншотов.

#### Scenario: Пустое состояние
- **WHEN** приложение только стартовало и ни одно окно не открывалось
- **THEN** `/state` отвечает: редактора нет, оверлея нет, документа нет — без ошибки; политика активации — `accessory`

#### Scenario: Состояние после открытия редактора
- **WHEN** редактор открыт на снимке с двумя элементами
- **THEN** `/state` перечисляет оба элемента с геометрией, указывает файл и наличие undo; политика активации — `regular`

#### Scenario: Геометрия открытого ввода
- **WHEN** агент открыл текстовый ввод и запросил `/state`
- **THEN** `text_editor_frame` содержит рамку поля в пикселях кадра, `text_editor_text` — текущую строку ввода; без открытого ввода оба поля `null`

#### Scenario: Политика следует за видимостью редактора
- **WHEN** окно редактора скрыто любым из путей закрытия и агент запрашивает `/state`
- **THEN** политика активации в состоянии — `accessory`, окно редактора не помечено видимым
