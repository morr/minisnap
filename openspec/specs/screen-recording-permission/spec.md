# screen-recording-permission Specification

## Purpose

Обращение с разрешением Screen Recording — единственным правом, которое нужно самому приложению (ScreenCaptureKit без него не отдаёт содержимое, ошибка -3801): при запуске право запрашивается штатным системным запросом, пока его нет — попытка захвата объясняет проблему диалогом, выданное право подхватывается без перезапуска.

## Requirements

### Requirement: Проверка при запуске
При запуске приложение SHALL выполнить непромптящий preflight права Screen Recording (`CGPreflightScreenCaptureAccess`). Если право не выдано, приложение SHALL вызвать системный запрос разрешения (`CGRequestScreenCaptureAccess`): запрос регистрирует текущую сборку в панели Конфиденциальность и безопасность → Запись экрана (без регистрации строки сборки в панели переключать нечего) и показывает системный промпт с переходом в System Settings. Собственный объясняющий диалог при старте SHALL NOT показываться — он дублирует системный промпт. Если право выдано, приложение SHALL запускаться тихо, без запросов и диалогов.

#### Scenario: Первый запуск без разрешения
- **WHEN** приложение запущено и право Screen Recording не выдано
- **THEN** текущая сборка зарегистрирована в панели «Запись экрана» и показан системный промпт выдачи разрешения; собственный диалог приложения при старте не показывается

#### Scenario: Промпт подавлен системой
- **WHEN** право не выдано и месячный лимит системного промпта (не чаще одного раза в месяц на приложение) исчерпан
- **THEN** приложение продолжает работать штатно; при попытке захвата объясняющий диалог указывает ручной путь — добавить minisnap в список кнопкой «+» в System Settings

#### Scenario: Разрешение выдано
- **WHEN** приложение запущено и право Screen Recording выдано
- **THEN** приложение стартует тихо, без промптов и диалогов

### Requirement: Захват без разрешения невозможен
Если право Screen Recording не выдано, попытка захвата — глобальный хоткей (capture или capture-edit) либо пункт меню Capture Frozen Area / Capture and Edit — MUST NOT запускать режим выделения и создавать снимок; вместо этого приложение показывает объясняющий диалог. Пункт меню Open Latest Image и его хоткей права не требуют и не блокируются.

#### Scenario: Хоткей без разрешения
- **WHEN** право не выдано и пользователь нажимает глобальный хоткей захвата
- **THEN** режим выделения не запускается, снимок не создаётся, показывается объясняющий диалог

#### Scenario: Пункт меню без разрешения
- **WHEN** право не выдано и пользователь выбирает пункт меню Capture Frozen Area или Capture and Edit
- **THEN** режим выделения не запускается, снимок не создаётся, показывается объясняющий диалог

### Requirement: Объясняющий диалог при попытке захвата
Объясняющий диалог MUST сообщать: что делает minisnap и почему без права захват не работает; какой раздел открыть — System Settings → Privacy & Security → Screen Recording; что сделать, если minisnap нет в списке, — добавить его кнопкой «+»; что сделать, если захват не заработал после выдачи, — завершить и заново открыть minisnap. Диалог SHALL иметь кнопку «Open System Settings», открывающую панель «Запись экрана», и кнопку «Not Now», закрывающую диалог без действий. Пока диалог открыт, повторная попытка захвата MUST NOT наслаивать второй диалог.

#### Scenario: Кнопка настроек
- **WHEN** пользователь нажимает «Open System Settings» в диалоге
- **THEN** Системные настройки открываются на панели «Запись экрана»

#### Scenario: Повторная попытка при открытом диалоге
- **WHEN** диалог открыт и пользователь снова нажимает хоткей захвата
- **THEN** второй диалог не показывается, захват не запускается

### Requirement: Продолжение после выдачи разрешения
После выдачи разрешения в System Settings приложение SHALL подхватывать его без перезапуска: каждая попытка захвата выполняет свежий preflight, поэтому следующий после выдачи захват работает. При активации приложения кешированное состояние права обновляется.

#### Scenario: Разрешение выдано после диалога
- **WHEN** пользователь выдал разрешение в System Settings и снова пытается захватить
- **THEN** захват начинает работать без перезапуска и без переустановки приложения
