# Единый путь рендера: черновик = зафиксированный элемент

## Диагноз — что происходит сейчас

Хорошая новость: почти всё уже устроено правильно. Закоммиченные элементы и на канве, и в композите рисуются одной функцией `render::draw_element` (`src/editor/render.rs:82`), и черновики фигур (стрелка, линия, прямоугольник, pen, блюр) идут через неё же: машина драга держит готовый `ElementKind`, `preview()` отдаёт его как extras, mouse-up коммитит **то же самое значение** в `Command::AddElement`. Для этих инструментов черновик и результат совпадают по построению.

Расходятся три места — весь класс описанных багов:

1. **Текст: два разных рендера.** Во время ввода текст рисует прозрачный `NSTextField` (AppKit-раскладка с её метриками строк), после Enter — Core Text `text::draw_text` с белым ореолом (`src/editor/text.rs:143`, проход stroke+fill). Следствия:
   - ореол появляется только после Enter;
   - совпадение двух раскладок по вертикали держится на подобранном вручную сдвиге `0.19·font_pt` (`src/editor_window.rs:1372–1380`) — это калибровка между двумя системами вёрстки;
   - кегль поля `(size·sy).max(9.0)` pt против `size` px у элемента;
   - поле имеет минимум 200pt ширины (`TEXT_EDITOR_WIDTH_PT`) и свою раскладку каретки — каретка стоит не в точке клика (200pt на 2x-дисплее ≈ те самые 200px);
   - при Enter окно **заново меряет** текст и зажимает блок в кадр `clamp_block` (`src/editor_window.rs:1629–1642`) → прыжок у краёв;
   - правка существующего: `EditText` якорь не двигает, а поле могло уехать внутрь кадра → прыжок обратно.
2. **Коллаут: черновик с заглушкой.** Пока печатается текст, канва рисует `Callout{text:""}` с `anchor=base` (`src/editor/drag.rs:643–655`) — хвост стрелки стоит в точке основания; при Enter `commit_callout_text` пересчитывает якорь через `callout_anchor`, хвост прыгает к краю текстового блока (`src/editor/render.rs:222–226`). Плюс блок поля имел набивку +12/+6pt, а коммитный — нет → сдвиг на несколько пикселей.
3. **Перенос/тяга конца: z-порядок и маркеры.** Призрак рисуется поверх всех элементов (extras в конце, `src/editor_window.rs:548–550`), а `MoveElement`/`MovePoint` меняют элемент на его месте в списке (`src/editor/mod.rs:226–236`) → элемент всплывает наверх на время драга и проваливается обратно; маркеры выделения рисуются от закоммиченного элемента (`src/editor_window.rs:651–653`) и отстают от призрака.

Вчерашний фикс `213f6ac` (text matrix identity) — смежный, но другой класс: утечка состояния чужого контекста в cached-рендере. Переделка его не трогает: `draw_line` остаётся единой функцией.

## Целевая архитектура

Принцип: **черновик — это уже элемент**. В процессе создания элемент существует как полный `ElementKind`, построенный тем же билдером, что и коммит, и рисуется тем же `draw_element` через существующую механику preview. Коммит замораживает уже построенное значение — прыжок невозможен по построению, а инвариант «preview.kind == commit.kind» проверяется юнит-тестом (сейчас такого теста нет).

### 1. Машина драга владеет набором текста (`src/editor/drag.rs`)

Сегодня состояние размазано: цель — в окне (`text_target`), живой текст — в NSTextField, геометрия коммита — в окне. Всё переезжает в чистую машину:

- состояние `TextDraft` { цель (origin+color для нового / id для правки), size, живая строка };
- API: `begin_text_draft(...)`, `update_text(&str)`, `update_text_size(f64, image)`, черновик в `preview()`, `commit_text(elements, image, next_id) -> Option<Command>` (новый → `AddElement`, правка → `EditText`/`DeleteElement`), `cancel_text()`;
- геометрия — только те же функции, что в коммите: `text::measure_block` → `clamp_block` / `callout_anchor`, пересчёт на каждый keystroke (у края кадра блок растёт внутрь по ходу ввода — для коллаута это уже норма спеки, распространяем на текст);
- `PendingCallout` получает живой текст: якорь и хвост стрелки — у края блока с первой буквы, прыжка при Enter нет;
- сборка `AddElement` для нового текста уходит из окна (`commit_text_editor`, editor_window.rs:1619–1643) в машину.

### 2. Окно: NSTextField → невидимый прокси ввода (`src/editor_window.rs`)

Поле остаётся машиной ввода (клавиатура, IME, выделение, Esc, клик мимо = коммит), но перестаёт быть дисплеем:

- текст поля прозрачный, видна только каретка (цвет — у field editor'а, `insertionPointColor`); выделение и подчёркивание IME — полевой хром, как маркеры выделения;
- рамка поля = рамка черновика блока в координатах вью — каретка сидит на тексте; `0.19·font_pt` и набивка `+12/+6` понижаются с геометрического контракта до хрома каретки;
- `controlTextDidChange` → `machine.update_text` + redraw: черновик перерисовывается канвой с ореолом тем же `draw_text`;
- умирают `TEXT_EDITOR_WIDTH_PT=200` и `.max(9.0)` (обслуживали видимый текст поля); `refit_callout_editor` сводится к рамке поля;
- fallback, если каретку не окрасить отдельно от текста: канвасная каретка по замеру префикса до insertion point той же Core Text метрикой.

### 3. Правка существующего текста

Элемент прячется на время правки (как сейчас), черновик рисуется от его якоря с живым текстом и клампом по росту. `apply_cmd::EditText` зажимает блок заново — прецедент уже есть: `apply_text_size`/`clamp_text_block` (`src/editor/mod.rs:465–475`). Схема журнала не меняется, реплей детерминирован, старые `commands.json` читаются как есть.

### 4. Z-порядок и маркеры при переносе/тяге концов

- `preview()` возвращает полный список отрисовки: призрак замещает элемент **на его индексе**, а не поверх всех; `EditorView::draw` рисует один список;
- `draw_markers` берёт геометрию из трансформированного призрака (запрос в машину), а не из закоммиченного элемента.

## Процесс и задачи

Проект работает через OpenSpec — начинаем с `/opsx:propose` change **`wysiwyg-draft-rendering`** (proposal + design + дельта спеки `shot-editor` + tasks). Дельта спеки: требование «при вводе текст рендерится тем же способом, что и зафиксированный» (ореол, кегль, позиция, каретка у текста), сценарии «нет смещения при Enter», «рост у края сдвигает блок внутрь по ходу ввода», «хвост коллаута у текстового блока и во время ввода», «перенос не меняет глубину элемента, маркеры следуют за призраком».

Задачи в `tasks.md` (по одной на коммит):

1. Машина: `TextDraft` + билдеры + `commit_text`; юнит-тесты инварианта «preview.kind == commit.kind» на сетке строк (пустая → символ → длинная → многострочная), кеглей и положений у краёв; тесты клампа по росту.
2. Окно: невидимый прокси (прозрачный текст, каретка, рамка = черновик), пересылка keystroke'ов и слайдера в машину, разборка контрактов 200pt/9pt/0.19.
3. `apply_cmd::EditText` зажимает якорь + тест реплея журнала.
4. Render-list вместо hide+extras; маркеры от призрака; тест порядка отрисовки при переносе.
5. Живая проверка через minisnap MCP: `scripts/build_app.sh release`, перезапуск экземпляра по PID, сценарии ввода у краёв/коллаута/переноса, окна спрятать после проверки.
6. Проход доменного скилла `minisnap-editor`: раздел про ввод текста и preview меняется — обновить по фактическому коду.

## Риски / места, решаемые в реализации

- цвет каретки независимо от прозрачного текста (`insertionPointColor` field editor'а; fallback — канвасная каретка);
- `controlTextDidChange` на IME-композиции (ожидаемо срабатывает — строка поля меняется; проверить на живой);
- клик внутри невидимого поля переносит каретку по полевой раскладке — при дрейфе метрик это считанные пиксели только у каретки, глифы больше не зависят от поля.
