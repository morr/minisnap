# Домен: заморозка кадра и выделение

По хоткею домен фиксирует кадры всех подключённых дисплеев и список видимых окон в момент T0 (`src/capture.rs`), показывает кадр дисплея под курсором полноэкранным оверлеем с UI выделения (`src/overlay.rs`; весь хром над кадром — `src/overlay_hud.rs`); пока режим активен, цель захвата следует за курсором — перевод его на другой дисплей переключает оверлей на его замороженный кадр. Результат — пиксельный прямоугольник плюс изображение — уходит в callback. Норматив — спека `frozen-capture`; сквозные конвенции (потоки, координаты, CGImage, objc2, контракт T0) — скил `minisnap-architecture`, здесь только их специфика. Не входит: запуск по хоткею и preflight (`app.rs`, `permission.rs`), кроп и сохранение (`output.rs`).

## Карта модулей

### `src/capture.rs` — снимок момента T0 (фоновый поток)

| Часть | Ответственность |
|---|---|
| выбор дисплея | целевой дисплей — под точкой (SCKit) |
| список окон T0 | видимые обычные окна, front-to-back — из оконного сервера (`CGWindowListCopyWindowInfo`), не из SCK |
| снимок | блокирующие вызовы ScreenCaptureKit, все дисплеи подряд в одном потоке; дисплей с неудавшимся кадром пропускается, ошибка на целевом — провал захвата |
| `mod geometry` | единственный конвертер координат (инвариант — спека `frozen-capture`) + сопоставление фреймов дисплеев с экранами |

### `src/overlay.rs` — полноэкранный оверлей заморозки

| Часть | Ответственность |
|---|---|
| публичный вход | окно+вью на весь процесс, переиспользуются (`show`/`is_active`/`cancel`) |
| objc2-классы | окно оверлея, вью событий, вью вуали |
| состояние | сессия в ivars-структуре вью; набор поверхностей T0, индекс цели, канал разрешения клика |
| исходы | внутренний запрос финиша и публичный результат (`OverlayOutcome::Selected`/`Cancelled`) |
| презентация цели | общий путь «показать поверхность на её паре-экране» для показа и переключения (`present_target`, приватный `mod presentation`) |

### `src/overlay_hud.rs` — HUD оверлея: весь хром над слоем кадра

| Часть | Ответственность |
|---|---|
| chrome-слои | dim-полосы, лупа с сеткой/перекрестием/двухтонной рамкой, оси, подпись, красная рамка с пульсом; один контейнер — второй ребёнок root |
| сэмплер | даунсэмпл кадра до логических пикселей (`FrameSampler`) |
| раскладка лупы | чистая функция с юнит-тестами: флип у краёв, клэмп сэмпла, снап к целым пунктам (`loupe_layout`) |

## Поток данных

Вход: `AppController::capture_ready` (гл. поток, тик в `src/app.rs`) → `Overlay::show(t0: T0Capture, on_done)`. Фрейм и скейл цели выходят из `SurfaceMap`: show строит спаривание поверхностей с `NSScreen::screens` один раз за сессию (приватный `mod presentation` — флип SCKit-фрейма + допуск) и кладёт его в ivars.

1. `OverlayView::show`: при `active` — игнор с логом (повторный вход). Иначе строится `SurfaceMap::for_surfaces` (без пары у стартовой цели — отказ с логом, ничего не показано); `surfaces`/`windows`/карта — в ivars; однократное цепление слоёв (`layers_attached`: root получает двух детей — кадр и `hud.attach`); активация приложения (`activateIgnoringOtherApps` + `activate`); `present_target(t0.target, screen)` — единый путь презентации (apply_target, idle-сброс, подмена кадра в `CATransaction`, `hud.present` — резкость хрома, путь рамки, сэмплер, fade-in/пульс, вуали, окно); отложенный `makeKeyAndOrderFront`. Состояние `Idle`.
2. `Idle`: `mouseMoved` — сначала дисплей под курсором: `NSEvent::mouseLocation` (глобальные AppKit-пункты; событие всё равно приходит key-окну, где бы курсор ни был) → `surface_map.switch_candidate(mouse, target)` — первая поверхность, кроме текущей, чья пара-экран содержит точку → `switch_to_surface`. На своей цели — прежний путь: `clamp_point` в границы дисплея → `hud.update`: лупа у курсора (кроп `FrameSampler::image` в лог. пикселях, nearest; размещение — чистая `loupe_layout`: флип у краёв, клэмп сэмпла, снап к целым пунктам), полные оси через курсор (двухтонные: белая обводка + чёрное ядро), подпись — координаты курсора.
3. Переключение цели (`switch_to_surface`): только гварды (повторный вход `active`/`finishing`, чужой индекс, отсутствие пары в карте — отказ с логом) и лог; всю работу делает `present_target` — единый путь презентации, общий с show: `apply_target` (новые кадр/фреймы/скейл) + `target`; сброс в `Idle` с очисткой HUD (`hud.hide`) и dim (`hud.dim(None)`); подмена `frame_layer.contents`/`contentsScale` и геометрии root-слоя внутри `CATransaction` с выключенными actions; весь хром под новый экран — `hud.present` (contentsScale хрома, перестройка пути рамки, пересборка `FrameSampler`, fade-in рамки и пульс заново); вуали (`rebuild_veils` — вуали переезжают: новая цель освобождается, прежняя накрывается); перенос окна `setFrame_display` + `makeKeyAndOrderFront`. show() отличается только обвязкой: приём данных сессии, цепление слоёв, танец активации; правка презентации — в одном месте, `present_target`.
4. `Drag`: `mouseDown` → `Drag`, пульс снят (`hud.stop_border_pulse`), дырка нулевого размера (полное затемнение, `hud.dim`); `mouseDragged` → прямоугольник (min/abs от `drag_start`) → `hud.dim` (4 чёрные полосы вокруг дырки) + подпись размера (`hud.update`); за краем — `clamp_point` (переключения в протяжке нет — `handle_mouse_moved` в `Drag` выходит рано); оси скрыты.
5. `mouseUp`: смещение от старта больше `CLICK_TOLERANCE_PT` — drag: `intersect` с экраном → `selection_to_pixel_rect` → `finish(Selected)`. Иначе клик: точка display-local AppKit переводится в SCKit-глобальные пункты через `geometry::display_point_to_pixel` (флип Y при scale 1) плюс оффсет `display_frame_sckit.origin`; список окон T0 клонируется, кадр клонируется, и разрешение цели уходит в фоновый поток (`std::thread`) — SCK нельзя звать синхронно из mouseUp: завершения SCK не доходят до main, заблокированного ответом. Ответ (пиксельный прямоугольник) приезжает по mpsc-каналу; канал лежит в `ivars.resolving`, тик приложения в `src/app.rs` зовёт `Overlay::poll_resolved_click`, который снимает готовый ответ и `finish(Selected)`; до ответа оверлей висит, гварды в `handle_mouse_down/up` глотают события мыши (режим завершается сам). Само разрешение — `resolve_click_target` (инвариант ниже): кандидаты по CG-порядку, победитель — рендер-проверкой, фолбэк — верхнее окно, мимо — весь кадр. Список окон T0 общий для всех дисплеев (фреймы окон не привязаны к дисплею), клик работает на любой цели. Сброс `resolving` — в `show()` и `finish()`: после отмены или повторного показа хвостовой канал не должен глотать клики нового сеанса.
6. `finish`: идемпотентен (`active` + `finishing`); вуали `orderOut`, `hud.hide` + `hud.drop_sampler` (логическая копия кадра — десятки МБ), `hud.stop_border_pulse`; `surfaces` очищены; `FinishRequest::Selected` + кадр и скейл текущей цели из ivars → `OverlayOutcome::Selected { pixel_rect, image, scale }` (кадра нет — `Cancelled`); окно `orderOut` немедленно — до колбэка, чтобы отклик на mouse-up не ждал обработку результата (кроп, звук, буфер, файл идут уже на открытом рабочем столе); `on_done(outcome)` — один раз.
7. Отмена → `Cancelled`: Esc (`keyDown`), клик по вуали (`VeilView::mouseDown` → `on_click`; при обычном переводе курсора недостижим — `mouseMoved` переключает цель раньше `mouseDown`, остаётся запасным путём для «телепорта» курсора), смена конфигурации дисплеев — два наблюдателя: `OverlayView::screenDidChange:` (NSWorkspace-нотификация) и `AppController::screenParamsChanged:` в `src/app.rs` → `Overlay::cancel()`.

Исход уходит в `src/app.rs`: `Selected` → `output::crop` → буфер/файл (скейл цели — суффикс `@2x` имени)/редактор.

## Инварианты и грабли

- Пиксельный размер кадра — только из `CGDisplayMode::pixel_width/height`; `SCDisplay.width` отдаёт пункты. `capture_display_image` задаёт размеры конфига из display mode — иначе Retina-снимок получится в пунктах.
- Список окон T0 — из `CGWindowListCopyWindowInfo` (`cg_visible_windows`): layer 0, есть владеющий процесс, только on-screen; собственные видимые окна minisnap участвуют наравне с чужими (норматив — спека `frozen-capture`). Фреймы и front-to-back порядок — истина оконного сервера, они совпадают с композитором (согласованы с AX). Список `SCShareableContent` для этого не годится: у окон, менявших размер вне штатного пути (winit/bevy-игра под оконным менеджером вроде loom), SCK держит устаревшие фреймы и фантомные записи; свежесозданные окна отсутствуют в нём минутами; порядок не следует композитору. Идентификаторы — общий `CGWindowID` namespace, поэтому SCK-список (свежий перезапрос в момент клика) остаётся источником `SCWindow`-объектов для рендер-проверки.
- Победитель клика — `resolve_click_target`: кандидаты — содержащие точку окна T0 в CG-порядке (не больше пяти), каждый рендерится отдельным SCK-скриншотом окна (без теней) и патч в точке сверяется с замороженным кадром; первый совпавший — цель. Порог строгий (`PATCH_MATCH_TOLERANCE`, средняя разница каналов): один и тот же контент через оба конвейера отдаёт единицы, а нестрогий порог (< 16) ложно совпадал на тёмных плоских участках — терминал «проходил» за игровую сцену. Никто не подтвердился (анимированный контент меняется между T0 и рендером, или у окна ещё нет записи в SCK) — фолбэк: верхнее содержащее окно по CG-порядку; содержащих нет — весь кадр.
- Координаты клика: фреймы окон T0 — глобальные пункты с началом в левом верхнем углу (пространство CGWindowList, оно же SCKit-глобальное); клик приходит display-local AppKit, перевод — `geometry::display_point_to_pixel` (scale 1) + оффсет `display_frame_sckit.origin`; патчи сравниваются в пикселях изображений (масштаб — фактический размер изображения на ширину фрейма, не ivars-скейл).
- Все переводы координат — только через `capture::geometry`; инвариант нормативно закреплён в спеке `frozen-capture` («Единственный конвертер координат»), карта пространств — в `minisnap-architecture`. Лупа и подпись координат говорят логическими пикселями — `display_point_to_logical_pixel` (pixel mapping / фактор сэмплера); проверка «точка в кадре» у `pick_display` и `switch_candidate` — одна `geometry::frame_contains_point` (полуоткрытые границы). `pixel_rect` исхода — в пикселях изображения, начало слева вверху; края округляются inward-safe (floor/ceil) и клампятся к кадру.
- Поверхность сопоставляется с экраном целым фреймом (origin + size) после флипа SCKit→AppKit по `primary_screen_height`, с допуском `FRAME_MATCH_TOLERANCE_PT` — по одному размеру два одинаковых монитора неразличимы. Спаривание — чистая структура `SurfaceMap` (приватный `mod presentation` в `src/overlay.rs`, `pub(crate)`-методы `screen_of`/`switch_candidate`): строится один раз при `show` и живёт в ivars до `finish`, поэтому `mouseMoved` не трогает `NSScreen`; список экранов за сессию не меняется — смену конфигурации дисплеев режим отменяет наблюдателем. Поверхность без пары-экрана не участвует в переключении (её слот в карте — `None`): её дисплей остаётся под вуалью до конца режима (поведение «дисплей без кадра T0» из спеки). `from_frames` и `switch_candidate` покрыты юнит-тестами на синтетических фреймах без живых экранов.
- Переключение цели — только в `Idle`; в `Drag` прямоугольник упирается в край дисплея. Повторный вход в `switch_to_surface` защищён теми же `active`/`finishing`, что и `show`. `present_target` сбрасывает состояние в `Idle` и прячет HUD/dim на обоих путях — сессия, оборванная Esc посреди протяжки, больше не протаскивает `Drag`, dim-полосы и геометрию рамки прошлого дисплея в следующую.
- Кадры всех дисплеев живут в ivars до конца режима (~60 МБ на 5K-дисплей); освобождаются в `finish()` вместе с текущим кадром. Латентность старта растёт на ~100–200 мс за каждый дополнительный дисплей — цена мгновенного переключения.
- Повторный вход защищён в трёх местах: `start_capture` и `capture_ready` в `src/app.rs` (проверка `is_active`) и сам `OverlayView::show`.
- HUD — один владелец, `Hud` (`src/overlay_hud.rs`): root-слой оверлея держит ровно двух детей (кадр и контейнер HUD), весь хром — дети контейнера в порядке z (dim-полосы, оси, лупа, подпись, рамка). Новый HUD-слой требует правок только модуля — `present_target` про состав хрома не знает (жёсткий список слоёв для contentsScale вынесен из шва в `Hud::apply_contents_scale`). Размер и масштаб экрана модуль запоминает в `present` — `dim`/`update` читают их каждый кадр; рассинхрон с ivars view невозможен (один писатель — `present_target` сразу после `apply_target`).
- `FrameSampler`: `ctx`, `buf`, `image` живут вместе — контекст не владеет байтами (они в `Vec`), изображение ссылается на буфер. Лупа читает не T0-кадр, а даунсэмпл (factor = `scale.round()`): показывает логические пиксели UI, а не физические; подпись размеров при drag — тоже логические пиксели, хотя спека говорит просто «в пикселях`. `buf` продакшн не читает (контент-адаптивную раскраску гайдов заменила константная двухтонная, `line_brightness_in` удалён) — поле помечено `#[allow(dead_code)]`, но обязано жить рядом с `image`; тесты сэмплера читают его напрямую.
- Обновления dim/HUD (`Hud::update`/`dim`/`present`) и подмена кадра T0 в `show` — внутри `CATransaction::setDisableActions(true)`: иначе Core Animation анимирует слои — лупа «плывёт» за курсором ~0.25 с, а `contents` слоя кадра кроссфейдится с кадром прошлого снимка и при повторном показе мелькает им. Снап лупы к целым пунктам и флипы у краёв — в чистой `loupe_layout` (юнит-тесты на синтетическом сэмплере).
- Клавиатура: borderless окно становится key только из-за override `canBecomeKeyWindow`; активация accessory-приложения — `activateIgnoringOtherApps: true` плюс отложенный повторный `makeKeyAndOrderFront`, иначе Esc молчит до первого клика.
- Оверлей и вуали — на уровне `CGShieldingWindowLevel()` (над строкой меню). Вуали пересоздаются на каждый `show` и каждое переключение цели (`rebuild_veils`).

## Живая проверка и диагностика

Стандартный прогон: запустить инстанс со stderr в файл (`./target/release/minisnap.app/Contents/MacOS/minisnap >/tmp/minisnap_out.log 2>&1 &`, правила идентификации инстансов — AGENTS.md), триггерить захват через трей-меню по PID (osascript `System Events`, у процесса один menu bar с одним айтемом — синтетические глобальные хоткеи не срабатывают), кликать драйвером, читать лог и размеры файлов в `~/Pictures/minisnap` (кроп окна = размер фрейма × 2 на Retina, суффикс `@2x`).

- `scripts/minisnap_drive.swift` — драйвер синтетического ввода (синтаксис режимов и сборка — в заголовке скрипта): клики/движения/нажатия, список окон оконного сервера (layer 0, front-to-back), список экранов, проверка Accessibility. Координаты — глобальные пункты левого верхнего угла (как в выдаче режима окон).
- `scripts/window_dump.swift` — оба списка окон рядом: `swift scripts/window_dump.swift [cg|sck]`. Этим сравнением и найдено расхождение SCK с реальностью (устаревшие фреймы bevy-окон, фантомные записи) — первый инструмент при «клик взял не то окно».
- Лог в stderr: постоянные однострочные маркеры `click: sckit point …` (клик дошёл до mouseUp), `click: matched window id=…` / `click: no candidate verified, topmost id=…` / `click: no window at the point, whole frame` (исход разрешения), плюс `overlay: …`, `output: saved …`. Отсутствие `click:` при живом клике — события не доходят до вью (см. ниже тайминг).
- `MINISNAP_CLICK_TRACE=1` при запуске — подробный трейс разрешения: кандидаты с фреймами, размеры рендеров, численная разница патчей (`dev=…`), включая `mouse-down` трассировку. Этим ловятся ложные совпадения (высокий `dev` при `matched=true` невозможен — порог виден в константе) и тихие пропуски кандидатов (`not in the SCK list`).
- Грабли тайминга: клик в первые ~0.2 с после появления оверлея может не дойти — mouseDown уходит окну под ещё не вставшим в стек оверлеем, mouseUp игнорируется (нет состояния Drag). В драйверных прогонах ждать строку `overlay: frozen` в логе и ещё ~0.5 с; живому пользователю человеческая реакция даёт запас.
