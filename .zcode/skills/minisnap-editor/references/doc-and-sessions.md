# Документ, журнал, сессии (`src/editor/mod.rs`, `src/editor/session.rs`)

## Команды (`Command`, `apply_cmd`)

| Команда | Эффект |
|---|---|
| `AddElement(el)` | элемент в конец списка (порядок = порядок рисования) |
| `DeleteElement(id)` | удалить по id (`retain`) |
| `MoveElement(id, delta)` | сдвиг всех координат элемента (`shift_element`) |
| `MovePoint(id, Endpoint, p)` | один конец стрелки/линии/коллаута (`set_endpoint`) |
| `EditText(id, text)` | текст Text/Callout |
| `Recolor(id, color)` | цвет у всех цветных видов; Blur — мимо |
| `SetWidth(id, w)` | толщина штриха (arrow/rect/line/pen); text/callout/blur — мимо |
| `Crop(rect)` | режет базу (`output::crop`, кламп в кадр, standardize) и сдвигает все элементы на −origin |
| `Resize(size)` | пересэмплирует базу (`redraw_at_size`: draw-then-snapshot, ориентация сохраняется, размер округляется до целых пикселей) и умножает координаты элементов на (sx, sy); толщины штрихов и кегль текста не масштабируются |

Команды детерминированы. Вырожденные `Crop`/`Resize` (пусто после клампа, нулевые размеры) не меняют состояние, но остаются в журнале; окно их не присылает — субпиксельная рамка не применяется (window-mechanics).

## `EditorDoc` — журнал и реплей

- Поля: `original` (нетронутый кадр — как снят или как открыт без сессии), `state { base, elements }`, `log`, `applied`. Инвариант: `state` = `original` + `log[..applied]`. После Crop/Resize `base()` отличается от `original()`; сессия хранит именно original.
- `apply(cmd)`: обрезать redo-хвост (`log.truncate(applied)`), добавить команду, применить. Undo/redo не строят обратных операций — только двигают `applied` и делают `rebuild`: полный реплей применённого префикса от `original`. Состояние не может разойтись с журналом.
- `apply_width(id, w)`: сливает подряд идущие `SetWidth` одного элемента в одну запись — условие слияния: журнал «чистый» (`applied == log.len()`, redo-хвоста нет) и последняя запись — `SetWidth` того же id. Тяга слайдера = один шаг undo. Чужой элемент или разрыв цепочки — новая запись.
- Id элементов — монотонные `u64`, не индексы: журнал остаётся валидным при удалениях. `next_element_id` = max id по всему журналу, включая redo-хвост (отменённые id не переиспользуются), + 1.
- `applied_log()` — применённый префикс: то, что undo может откатить и что пишется в сессию.

## `OpenShot` и автосохранение

- `OpenShot { doc, shot_path, sessions_root }`. Любая операция (`apply`, `apply_width`, `undo`, `redo`) заканчивается `persist`: `render_composite(doc.base(), doc.elements())` → `output::encode_png_atomic(&composite, &shot_path)` + `store_commands(root, path, doc.applied_log())`. Файл снимка после каждой команды соответствует изображению в окне. Ошибка `persist` возвращается строкой и печатается вызывающим (окно), но не откатывает `doc` — возможна рассинхронизация файла и состояния до следующей успешной записи.
- `OpenShot::open(path, root)`: `load` удался (есть читаемый `original.png` и валидный `commands.json`) → `EditorDoc::new(original)` + реплей всех команд файла. Любая неудача (нет каталога, не читается оригинал, нет или битый JSON, ошибки только в stderr) → fresh: файл снимка декодируется и становится `original`, тут же `store_original` в новую сессию. Redo-хвост в файл не пишется — после переоткрытия redo нет.

## Сессии на диске

- Корень `default_root()` = `/tmp/.minisnap`; сессия снимка — `<root>/<stem имени файла>/`: `original.png` (пишется один раз при открытии fresh-сессии) и `commands.json` (переписывается целиком после каждой команды). Ключ — только stem, без папки: у файлов с одинаковым stem из разных папок сессии столкнутся (на практике снимки живут в одной папке сохранения).
- Обе записи атомарные: tmp-файл + `rename` (`write_atomic`) — крах посреди записи не оставляет половину файла.
- `enforce_retention(root, MAX_SESSIONS = 50)`: держит 50 самых свежих по mtime каталогов, старшие удаляются best-effort (неудаляемые логируются и пропускаются). Запускается после каждой записи журнала.
- OS очистила tmp → сессий нет → деградированный режим «без истории»: снимок открывается с пустым журналом, его файл становится новым оригиналом; редактор полностью работоспособен. Листание ◄/► открывает соседние снимки папки, каждый со своей сессией.
